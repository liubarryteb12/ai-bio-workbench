## 七、已知坑（血泪，按主题）

### 7.1 runit / Termux

- **runit 只记 fd1**：`log/run` 是 `exec cat >> <logfile>`，脚本里写 `>&2` 的告警在日志里完全看不到。
  四段式模板要求 `exec 2>&1` 紧跟 `set -eu`。
- **`sv` 一律给绝对路径**：`sv status $PREFIX/var/service/sshd`。只写服务名报 `unable to change to service directory`。
- **`sv down` 对 proot 容器无效**：TERM 落在 proot 包装进程上，容器里的 dropbear 照跑，stat 停在
  `run, got TERM, want down`。要真停得再杀 dropbear 进程。这种形态被归一化成 `down_pending`，
  并在心跳里产出 `ANOMALY_STOP_IGNORED`。
- **runsvdir 会改写自己的 argv**：健康实例是 `.../bin/runsvdir <SVDIR>`（没有 `-P`），
  野生态是 `runsvdir .../bin/runsvdir <SVDIR>`（argv0 被复制）。判据按 argv 位置，别 grep 整行。
- **`kill $(pgrep -f dropbear-static)` 会杀掉承载自己的 sh**，命令以 SIGTERM 返回。用 `[d]ropbear` 括号技巧或先取 pid。
- 非交互 ssh 会话 PATH 里没有 `$PREFIX/bin`，脚本里一律写绝对路径 `/data/data/com.termux/files/usr/bin/bash`。

### 7.2 SELinux 域（最坑的一处）

- `adb exec-out run-as com.termux ...` 起的东西落在 **runas_app** 域，该域 `runsvdir` 起 runsv 报
  `fatal: unable to start runsv <svc>: access denied`，且跨域 `kill` 静默失败（返回 0，进程不动）。
- 正确恢复通道：`adb shell am force-stop com.termux` → `monkey -p com.termux -c android.intent.category.LAUNCHER 1`
  → 预置 `~/bin/boot_repair.sh` → `adb shell input text 'bash%s~/bin/boot_repair.sh'` + `input keyevent 66`，
  在 app 域（`untrusted_app_27`）里 `nohup setsid flock -n <lock> runsvdir -P <SVDIR> &`。
- 跨域残骸只能 `adb shell 'run-as com.termux kill -9 <pid>'` 清。全过程见 `docs/k40_runit_recovery.md` 第五节。

### 7.3 心跳 / 观测

- `/proc/net/tcp` 对 app uid 恒 `Permission denied`（ssh 与 run-as 两条路都不行），端口探活只能用
  `bash -c 'exec 3<>/dev/tcp/127.0.0.1/8022'`。每次探测会在日志留 1 到 2 行，所以按需执行、不常驻。
- 容器里的 `/mnt/ssd` 是容器内绑定路径，宿主真身是
  `$PREFIX/var/lib/proot-distro/containers/ubuntu/rootfs/mnt/ssd/bio_data`（没有 `installed-rootfs` 这个目录）。
- `ps -A -o pid,args` 经 ssh 给全路径、经 run-as 只给基名，两种形态都要认。`lstart` 在 Android 上是假的。

### 7.4 测试与变异

- 变异必须用**函数式 replacement**：字符串替换里 `$$` 会折叠成一个 `$`，写 `$$` → `$$$` 实际不生效（报 NOOP）。
- **等价变异不算断言有洞**：把「成功时写 last_ok_ts」改成「无条件写」语义没变，测试必然绿；要换成
  「写当次时间戳」这种真能改变行为的写法。
- 函数体切片禁用固定窗口（`+900` 字符会溢到邻居函数造成假绿），用「从 `name() {` 到紧随的独占 `}`」。
- 静态契约先滤注释行（注释里也有 ` -P `、`want down` 这类字面量）。
- `[ref]$errs` 前必须 `$errs = $null`，否则 ParseFile 检查自己报错却照样打印 PARSE_OK（假绿）。

### 7.5 工具链

- **PowerShell 没有 heredoc**：`<<'EOF'` 报 ParserError。多行文本一律 `write` 到 `.tmp/*.txt` 再用
  `git commit -F .tmp/commit_msg.txt`。
- `run_code` 的 TS 模板串里写 shell 会被 `${...}` 插值：先把 `$` 写成 `§`，最后 `.split('§').join('$')`；
  反引号同样会终止字面量。更稳的做法：把脚本 `write` 成 `.cjs` / `.sh` 文件再跑。
- `Get-Content -Raw | ssh k40 "cat > file"` 会给行尾补 CR，必须再 `sed -i 's/\r$//' file`。
- **ps1 含中文必须存 UTF-8 带 BOM**：这台机器没有 pwsh 7，脚本喂进 Windows PowerShell 5.1 时
  无 BOM 的 UTF-8 按 ANSI 代码页解码，中文注释尾字节吃掉紧邻引号，`node @args` 收到残缺
  argv（实测 `bad option: --project-id`）。`delivery_acceptance.test.js` 钉住 BOM 三字节。
- **run_code 的 `process.env` 是空的、`process.execPath` 是宿主 exe**：起 npm/ssh/node 的
  子进程必须先用 PowerShell 把真环境 dump 成 JSON 再 Object.assign 重建，PATH 里补
  `D:\node-v2.4` 与 `D:\Git\usr\bin`（否则 Windows OpenSSH 找不到 Git 的 key 报 255，
  npm test 的链路测试成片假红）；跑测试一律用 `D:/node-v2.4/node.exe`，别用 execPath。
  子进程 stdio 走文件描述符或 `> file 2>&1`，命名管道在该沙箱里被禁（EPERM）。
- bsk 故障 playbook：tab 级操作恒报 `Previous operation is still settling` 时，`wait` → `session stop`
  → 重新 `start` → 需要时 `tab borrow`。`bsk_inspect screenshot` 超时是扩展 0.4.0 的故障源，别重试。
