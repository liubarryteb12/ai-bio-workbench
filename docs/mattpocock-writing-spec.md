## 一、Context pointer

**context pointer** 是 agent 上下文里一条引用，它点名一段不在上下文里的材料，
并编码"什么时候去够它"的条件。skill 的 `description` 是一条，`AGENTS.md` 里指文档的那行也是同一个东西。

决定 agent 何时、多可靠地去够那段材料的，是 pointer 的**措辞**，不是它指向什么。
必须的材料挂在弱措辞后面，是方差 bug：先磨措辞，磨不动了才把材料内联进来。

一条 pointer 干两件事：说清材料是什么，列出该触发它的**分支**
（分支是文档处理的一个独立情形，不同轮次走不同路径）。常驻 pointer 的每个字每轮都花钱，
所以它比正文更该修剪：

- **leading word 前置**：pointer 就是干触发这件活的。
- **一个分支一个触发词**。给同一个分支换说法的同义词，是同一个分支写了两遍，合并。
- **正文已经承载的身份信息删掉。**

## 二、两份负载

你加的每份文档、每条 pointer，花的是两份预算之一。

**上下文负载**是常驻材料对 agent 窗口的开销：`AGENTS.md` 一行、skill 的 description、
任何每轮都坐在上下文里的东西，不管它是否触发都在花 token 和注意力。
**认知负载**是对人的开销：有哪些文档、什么时候够哪份。人就是索引。
这不是要最小化的成本，是人能动用的主观判断权的价格：
人的判断要紧的地方就花，不要紧的地方就撤。

只靠指针够到的材料，用 pointer 那一行的代价换掉上下文负载；
完全没有指针的材料，全靠认知负载。

## 三、信息层级

文档由两种内容构成：**steps**（agent 依次执行的动作）和
**reference**（按需查阅的定义、规则、事实）。两者自由混合。
核心决策是每块落在**信息层级**的哪一级，按 agent 多需要它来排：

1. **in-file step**，主层级：agent 按顺序做什么。
2. **in-file reference**，按需查阅。常常合法地平级铺开（一份评审的所有规则同一级），
   这是合理排布，不是味道。
3. **disclosed reference**，被推到单独文件，靠 context pointer 指，
   只在 pointer 触发时才加载。从同目录的兄弟文件一直到完全外部都算。

推得不够，顶层臃肿；推得过头，把 agent 真需要的材料藏起来了。这个张力就是全部决策。

**progressive disclosure** 是往下层走、挪到指针后面，让顶层保持可读。
它主要不是省 token，是保护层级结构。最干净的判别式是**分支**：
所有分支都要的内联，只有部分分支够到的下推。
有 steps 的文档里，本该下推的 in-file reference 会埋掉 steps，
让"注意它"变成抛硬币：这是方差杠杆，不只是可读性杠杆。

**co-location** 是文件内的配套：层级决定一块**下得多深**，co-location 决定它下来之后**旁边放什么**。
把一个概念的定义、规则、坑放在同一个标题下，而不是散着，
这样读一处就把邻居带来了。判据：文档读起来该像**写给 agent 的文档**。
分组放着读起来就像，散着就不像。（与 duplication 不同：那是一个意思在两地重复；
scattering 是一个意思碎在很多处。）

**sprawl** 是这里的失效模式：文档太长，哪怕每行都活着、都唯一。
注意力在余量上摊薄，每多一行就多一行要维护。药方就是层级：
reference 下推到指针后面，按分支或时序拆开，让每条路径只带它要的。

## 四、步骤与完成判据

每个步骤终于一个**completion criterion**：告诉 agent 活干完了的条件。两个性质决定它是杠杆：

**清晰度**：agent 分得清做完和没做完吗？模糊的边界（"达成理解"）招来
**premature completion**：步骤还没真完就收尾，注意力滑向"已经做完了"。
挡它按这个顺序：**先把边界磨尖**（局部且便宜）；
只有边界真的没法磨尖**且**你观察到那种抢跑，才靠拆序列把后面的步骤藏起来。
隐藏只在跨越真实上下文边界时有效（交接或子代理派发）；
内联调用会把后面的步骤留在上下文里，什么都清不掉。

**要求量**：它要求多少。"每个改动的 model 都交代清楚"迫使做扎实的活，
"产出一份变更清单"不会。要求量驱动**legwork**（agent 在活里做的挖掘，
潜伏在措辞里而不是写成自己一步），而且它不受步骤约束：
"每条规则都应用了"约束一叠平铺的 reference，跟"每步都做了"约束一个序列一样，
这就是一份纯 reference 文档照样带穷尽性门槛的方式。

最强的判据既**可检查**又**穷尽**。

## 五、什么时候拆

拆一份文档花的是上面两份预算之一，所以只有这一刀划得来才拆：

- **按时序拆**：后面的步骤诱使 agent 草率对待眼前这步的那一串。让后面的步骤不在视野里，
  逼出更多 legwork。反过来也要当心：合掉序列会把每步的后续暴露给后面，
  招来 premature completion。
- **按调用方式拆**（skill 专属）：见下面第七节。

## 六、Leading word

**leading word** 是一个已经活在模型预训练里的紧凑概念，agent 跑文档时拿它来想
（_lesson_、_fog of war_、_tracer bullet_）。当 token 反复出现，不当句子用，
它会积累出分布式定义，用最少的 token 锚住一大片行为，靠的是征用模型已经有的先验。
自己造词也行，只要定义清楚，但生造的词征用不到先验：
你花定义 token 去买预训练词免费给的东西。先用现成的词。

它锚两处。正文里锚**执行**：这个词每次出现，agent 都去够同一个行为，
在平铺 reference 里则把注意力聚到一类要找的东西上。
pointer 里锚**调用**：当同一个词活在提示词、文档、代码库里，
agent 会把这套共享语言连到材料上，够得更可靠。

主动找机会用 leading word 重构。三处展开讲的一个三元组，
一条 pointer 花一句去比划一个想法，都是一段在求着塌成一个 token 的段落：

- "快、确定、低开销" → _tight_（一条 _tight_ 的环）。
- "一个你信得过的环" → _red_，把模糊的门变成二元可观测状态（环对这个 bug 变 _红_ 或者没变）。

赢两次：token 更少，agent 挂思考的钩子更锐。
假定每份文档都带着一些 leading word 能退掉的复述，去找。

**negation** 是旁边那个失效模式：靠禁令转向，会把被禁的行为拽进上下文，
让它**更**可及而不是更不可及。别想大象，于是满脑子都是大象；
否定是个弱修饰语，被强激活的概念直接压过，于是禁令有一半读起来像是让做那件事的指令。
**prompt the positive**：说清目标行为（"写单行注释"），被禁的那半就根本不出声。
禁令只在硬护栏、且没法正面表述时才配占位置；即便如此也配上正面目标，
让注意力落在该做什么上。

## 七、Skill 专属机制

两个选择，交换的是两份负载：

- **model-invoked** 保留 `description`，agent 能自主触发，别的技能也够得到它。
  你照样能打字调它：model-invocation 永远**包含**人的可达，
  description 只会加 agent 的发现，不会拿走人的。
  代价是常驻上下文负载，换来可发现性。
  纯 reference 的 model-invoked 技能还是一处共享参考的家：别的技能能调它，
  于是几个技能都要的参考住在一处。
- **user-invoked** 把 description 从 agent 的 reach 里摘掉：只有人打字能调，
  别的技能都不行。零上下文负载，但花认知负载：你就是那个必须记得它存在的索引。

只有当 agent 必须自己够到它、或别的技能必须够到它时，才选 model-invocation。
只靠手打就够它活的，做 user-invoked，不付上下文负载。

两个 user-invoked 技能都要的共享参考，住不到任何一边：没有 description，谁也调不到谁。
把它推到 skill 系统外面的普通文件，做任何技能都能指的 external reference。

**按调用方式拆**：当你有一个独立的 leading word 该自己触发它
（一个你真会在提示词里用的触发词），或别的技能必须够到它，就拆出 model-invoked 技能。
你为新那条常驻 description 付上下文负载，所以那份独立可达性得值这个价。

**router skill**：user-invoked 技能多过你记得住的时候，堆起来的认知负载由一个
**router skill** 治：一个 user-invoked 技能点名其余那些以及什么时候够谁，
于是人只需记一个。它只能提示，永远触发不了它们：
user-invoked 没有 description，除了人谁也够不到。

## 八、修剪

- 一个含义放**单一真源**。**duplication** 花维护和 token，
  还会把一个含义在层级上的显眼程度抬到超过它真实的排位。
  （它是 leading word 的意外反面：那个是有意重复 token，从不重复含义。）
- **环境也是真源**（`package.json` scripts、配置文件、目录布局、`--help` 输出）。
  复述环境的文档是**缓存**：一份查找表的副本，只在查找很贵时才配得上它的负载。
  缓存 agent 查不到的东西：不成文的约定、选择背后的理由、配置不肯招的坑。
  一条命令一个文件的查找留给环境，那儿不会过期。
- 每行查**相关性**：它还管不管这份文档干的事？
  一行会因两件事失相关性：从来不管这个活（纯粹铺陈，或本该下推的分支），
  以及它描述的行为或世界变了而它过期了。文档越短越容易保持相关性。
  没有修剪纪律，默认结局是 **sediment**。
- **逐句猎 no-op**：一条模型默认就会照办的指令，花负载说什么也没说。
  判别式（相对默认行为有没有改变？）是**模型相关**的，不是读者相关：
  两个人对一个 no-op 有分歧，是对默认行为有分歧，靠跑文档解决，不靠辩。
  不通过的整句删掉，不从里面抠字眼。这个判别式也评 leading word：
  弱到压不过默认行为的词（agent 本来就挺 thorough，你还写 _be thorough_）是 no-op，
  药方是更强的词（_relentless_），不是换技术。

## 九、落地的三条硬规矩

1. **`AGENTS.md` 只放导航指针。** 它每轮都进上下文，按上游规范要极度省着用。
   流程、规范正文、模板放 skill 或被指针指的文档里。
2. **review agent 执掌标准，不是实现 agent。** 实现 agent 上下文压力最大
   （要探索、写码、调试），review agent 压力最小（只收到一个 diff）。
   所以机械类违规上确定性检查（linter 自定义规则、pre-commit、CI job），
   `CODING_STANDARDS.md` 只留给判断题。
3. **没有 em dash。** 上游仓库全文禁破折号，中文写作同样用逗号、冒号、句号、括号。
   句子够到它时，重写这句话，不要做盲字符替换。
