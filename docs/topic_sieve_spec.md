# 非肿瘤 · 非免疫方向｜生信课题设计框架与数据筛选规范（筛子 v1.0）

> **本文档定位**：不是数据集清单，是一张**筛选框架 + 课题生成规则**。
> **疾病名留空**，由填表人自行填入符合"非肿瘤、非免疫"准入的任意疾病。

## 第一部分 · 先解释你问的两个字段

### 1.1 参考基因组版本（GRCh38/hg38、GRCm39/mm10、GENCODE v4x）

**它是什么**：RNA-seq 拿到的原始 reads 是一堆短序列片段，必须"贴"到一份标准参考序列上才知道它属于哪个基因。这份标准序列就是参考基因组，它的发布版本号就是参考基因组版本。

| 物种 | 版本对 | 说明 |
|---|---|---|
| 人 | **GRCh38 = hg38**（同一版本的两种叫法，前者 Ensembl/NCBI 命名，后者 UCSC 命名） | 当前主流，建议统一用这个 |
| 人 | GRCh37 = hg19 | 老数据常见，仍在大量旧队列中使用 |
| 鼠 | **GRCm39 = mm39** | 较新 |
| 鼠 | GRCm38 = mm10 | 目前鼠源数据里最常见的版本 |

**GENCODE 版本**（如 v44 / v40 / M33）：光有基因组序列还不够，还需要一份"基因都在哪些坐标上"的注释文件（GTF/GFF）。GENCODE 就是这套注释的版本号。人源是 `v` 开头（GENCODE v44），鼠源是 `M` 开头（GENCODE M33）。

**为什么这个字段必须记录**：

1. 不同版本的**染色体坐标不同**（同一基因在 hg19 和 hg38 上的位置不一样），做坐标相关分析（如 eQTL、peak 注释、CNV 关联）时会全错。
2. 不同版本的**基因集合与基因 ID 不同**，有些基因在新版本被合并、拆分或改名。
3. 最实际的坑：你拿到作者的 counts 矩阵（hg19 定量）和另一套数据（hg38 定量），直接按基因名取交集时，会有一部分基因对不上，差异分析结果会静默失真。**记录版本 = 提前知道要不要做 ID 转换。**

**芯片不需要这个字段**。芯片靠探针杂交，不涉及序列比对，它对应的是下面要讲的"注释包"。**这是芯片与 RNA-seq 在数据治理上的第一个分水岭。**

---

### 1.2 定量来源（作者提供 counts / 需自己从 fastq 走 Salmon-STAR）

**它是什么**：bulk RNA-seq 最终你要的是一个"基因 × 样本"的表达矩阵。这个矩阵从哪来，只有两条路：

| 路径 | 操作 | 成本 | 适用 |
|---|---|---|---|
| **A. 作者提供 counts** | GEO 的 Supplementary 里直接下载作者上传的 `raw_counts.csv` / `counts.txt` / `gene_counts.csv`，直接进 DESeq2 / limma-voom | 极低，下载即用 | **首选** |
| **B. 自己从 fastq 定量** | 拿 SRA/ENA 的 fastq，自己跑比对与计数 | 高，需算力+时间+版本决策 | 仅在 A 不可得且该队列不可替代时使用 |

**路径 B 的两条技术路线（你提到的 Salmon-STAR）**：

- **STAR + featureCounts（比对派）**：STAR 把 reads 比对到参考基因组 → featureCounts 按 GTF 统计落在每个基因上的 reads 数 → 得到整数 counts。**精度高、能发现新转录本，但慢、吃内存（~32GB+）**。
- **Salmon / kallisto（伪比对派）**：不真正做全基因组比对，直接把 reads 比对到参考转录本（cDNA）上，用 EM 算法估算每个转录本的表达量。**快 1~2 个数量级、内存友好，但拿不到比对坐标信息**。
- **组合用法（最常见的现代方案）**：Salmon 定量到转录本 → `tximport` 包汇总到基因水平 → 进 DESeq2。**这就是通常说的 "Salmon-STAR 流程" 的两条支线**，"STAR" 在这里指代以比对为基础的经典路线。

**判断规则（写进筛子）**：

1. **优先作者 counts**。只要 GEO Supplementary 里有 counts 文件，一律走路径 A，直接把"定量来源"填为 `作者counts`。
2. 只有 **TPM / FPKM / RPKM** 而**没有 counts** 时：注意 **TPM/FPKM 不能直接进 DESeq2/edgeR**（它们要求整数 counts），只能用于 limma 差异分析、相关性、热图展示。此时填 `仅TPM/FPKM`，并降级。
3. 只有 fastq：填 `需自建定量`，并在打分卡里扣算力分。**本框架不把 raw fastq 设为硬门槛**（你的要求），但自建定量会显著拉长课题周期，需在立项时折算成时间成本。
4. **单细胞与空间数据通常不存在这个选择**，它们一般以 10x 三件套或 h5ad 形式直接提供，不需要你重新定量。

## 第二部分 · 框架总览：五层漏斗

数据从"搜到"到"能立项"，要连过五关。每关都有明确的判据，不合格直接出局，不再消耗后续精力。

```
L0 疾病准入 ──→ L1 要素卡填写 ──→ L2 单数据集可用性评分 ──→ L3 成链判定 ──→ L4 课题反推与立项
   (排除/纳入)      (字段完整性)      (A/B/C 分级)         (能否串成链)      (能做什么课题)
```

| 层级 | 判定什么 | 出局条件 |
|---|---|---|
| **L0** | 疾病是否落在非肿瘤、非免疫范围 | 触及排除清单即出局 |
| **L1** | 必填字段是否填全 | 关键字段缺失且无法补充即出局 |
| **L2** | 单个数据集的可用性强弱 | 评分 < 60 分转为备选，不作为核心件 |
| **L3** | 多个数据集能否串成一条逻辑链 | 缺"必选件"则该链条不成立 |
| **L4** | 这条链支撑得起哪类课题 | 无任何课题模板可匹配 → 数据作废 |

## 第三部分 · L0 疾病准入规则

### 3.1 硬排除清单（触及即出局）

- **肿瘤方向**：各类癌（癌/腺癌/鳞癌/肉瘤/黑色素瘤/胶质瘤）、血液系统恶性病（白血病/淋巴瘤/骨髓瘤）、肿瘤微环境、肿瘤免疫治疗应答、癌前病变的恶性转化研究。
- **免疫方向**：自身免疫与免疫介导病（RA / SLE / 干燥综合征 / 系统性硬化 / 多发性硬化 / IBD / 银屑病 / 特应性皮炎 / 1型糖尿病）、免疫细胞发育与分化机制、移植排斥与免疫耐受、感染的免疫应答机制、免疫检查点与免疫治疗。

### 3.2 边缘疾病判定规则（人工判，但要有依据）

> **判据**：若该疾病的主流文献把"免疫细胞浸润 / 自身抗体 / 炎症因子风暴"作为**核心发病机制**来论述 → 判为免疫方向，**排除**。
> 若免疫改变只是**次要伴随现象**或**下游结果** → **可纳入**，但必须在要素卡备注栏写明"含免疫成分，机制定位为次要"。

**典型边缘案例**（供填表人对齐口径）：

| 疾病 | 判定 | 理由 |
|---|---|---|
| 哮喘、COPD | ⚠️ 边缘 | 气道炎症为核心机制，倾向判为免疫方向；若课题聚焦气道重塑/平滑肌/纤维化，可纳入并备注 |
| 动脉粥样硬化 | ✅ 可纳入 | 脂质代谢与斑块稳定性为主，免疫为参与因素 |
| IPF（特发性肺纤维化） | ✅ 可纳入 | 纤维化与上皮-间质转化为主 |
| 2型糖尿病 | ✅ 可纳入 | 代谢为主；1型糖尿病因自身免疫机制 → 排除 |
| 创面愈合、瘢痕 | ✅ 可纳入 | 修复与重塑为主 |
| 子宫内膜异位症 | ⚠️ 边缘 | 有免疫与激素双重成分，需按课题聚焦点判定 |
| 脓毒症 | ❌ 排除 | 免疫应答为核心 |

### 3.3 可纳入方向示例（不穷尽，填表人自填）

代谢与内分泌（NAFLD/NASH、T2D、肥胖、血脂异常、PCOS）· 心血管（心梗、心衰、动脉粥样硬化、心肌病、房颤、高血压靶器官损伤）· 神经（AD、PD、ALS、HD、脑卒中、癫痫、神经病理性疼痛、周围神经病）· 肾脏（CKD、AKI、DKD、肾纤维化）· 肺非肿瘤非免疫（IPF、肺动脉高压）· 骨骼肌肉（OA、骨质疏松、肌少症、肌营养不良、椎间盘退变）· 感觉器官（AMD、糖尿病视网膜病变、青光眼、听力损失）· 发育与衰老 · 生殖与妊娠（子痫前期、早产）· 皮肤非免疫（脱发、色素异常）。

## 第四部分 · L1 要素卡：四类数据的字段模板

> 使用说明：一个 GSE 填一张卡。SuperSeries 拆成多个 SubSeries 时，**每个 SubSeries 单独填一张**（见第十部分坑 #1）。

| 标题/简述 | 一句话概括设计与目的 | ✅ |
| 物种 | 仅二选一：**Homo sapiens（人源）** / **Mus musculus（鼠源）** | ✅ |
| 组织来源 | 器官 + 具体部位（如"肝脏 · 穿刺活检"） | ✅ |
| 总样本数 | 填实测值，无最低门槛 | ✅ |
| 分组方案 | 疾病 vs 正常 / 治疗应答 / 分期 / 时间梯度 / 基因型 | ✅ |
| 每组样本数（或 donor 数） | 逐组列明 | ✅ |
| 训练/建模角色 | 发现队列 / 内部验证 / **外部独立验证** / 参考资源 | ✅ |

### 4.5 数据可得性档位（三档，processed 优先、raw 非必须）

| 档位 | 定义 | 处理成本 | 评分 |
|---|---|---|---|
| 🟢 **processed 直给** | 直接提供表达矩阵 / h5ad / Seurat 对象，下载即可进分析 | 极低 | 25 分 |
| 🟡 **有中间态** | 10x 三件套、counts 表、CEL 文件、需一步转换 | 低~中 | 15 分 |
| 🔴 **仅 raw fastq** | 必须从 fastq 自建定量 | 高（算力+时间） | 5 分 |

> 按你的要求：**raw fastq 不作为硬门槛**。🔴 档数据仍可入选，但会在评分中体现成本，并在立项时折算周期。

## 第五部分 · L2 单数据集可用性评分卡

满分 100，六个维度加权，按得分分三级。

| 维度 | 权重 | 评分细则 |
|---|---|---|
| **数据完整性与可得性** | 25 | 🟢=25 / 🟡=15 / 🔴=5；缺关键文件（如空间图像、10x 三件套）每个再扣 5 |
| **分组清晰度** | 20 | GSM↔分组可完整映射且定义明确 = 20；摘要含糊但可推断 = 10；无分组信息 = 0 并出局 |
| **规模** | 15 | 同类型数据中的相对分位：上四分位=15，中位=10，下四分位=5（**不设绝对门槛**） |
| **临床信息丰富度** | 15 | 有分组外的协变量（年龄/性别/分期/用药）=10；另有随访时间+结局 = +5 |
| **物种与组织匹配** | 15 | 与课题疾病+组织完全一致 = 15；组织一致物种不同 = 8；仅物种一致 = 5 |
| **下载可达性** | 10 | 公开直链 = 10；需注册/镜像 = 6；受控访问（如 dbGaP 需申请）= 3 |

**分级判据**

| 等级 | 分数 | 处置 |
|---|---|---|
| **A 级** | ≥ 80 | 核心候选，可作为发现队列或主验证队列 |
| **B 级** | 60 ~ 79 | 可用补充件，做内部验证或参考资源 |
| **C 级** | < 60 | 备选/淘汰，仅在 A、B 均缺位时启用，且需在立项说明中标注风险 |

**一票否决项**（无论分数，直接出局）：
- 无分组信息，或分组与疾病状态无关
- 分组与测序批次**完全混杂**（如疾病组全在批次1、正常组全在批次2，无法用任何方法校正）
- 人源数据受控访问且申请周期不可控
- 同一队列被拆成多个 GSE 重复入库，实为同一批样本（需查 BioProject 去重）

## 第六部分 · L3 成链判定：四种串联模式

> **核心原则先讲清楚**：四类数据之间的"配套要求"分**强、弱两档**，很多检索失败是因为把弱配套误当强配套，白白筛掉大量可用数据。

### 6.1 强配套 vs 弱配套（本框架最重要的松绑规则）

| 关系 | 配套强度 | 要求 | 说明 |
|---|---|---|---|
| **bulk 发现 ↔ 芯片验证** | 🔴 **强** | 必须同疾病、同组织、分组定义可比 | 否则外部验证不成立，模型 AUC 无意义 |
| **bulk/sc/ST 的关键基因串联** | 🔴 **强** | 必须同疾病、同组织 | 基因在不同疾病间不可迁移 |
| **sc ↔ ST** | 🟠 中 | 同组织优先；不同研究可接受 | 反卷积允许用同组织不同研究的 sc |
| **sc 的注释参考** | 🟢 **弱** | 可用公共图谱 | CellTypist / SingleR / Azimuth 的泛组织参考集即可，不要求同疾病 |
| **ST 的反卷积参考** | 🟢 **弱** | 可用公共图谱 | 可用公开正常组织 sc 图谱作参考 |
| **跨物种（人↔鼠）验证** | 🟢 弱 | 人源发现 + 鼠源验证，或反之 | 只需保守基因层面可比，允许不同研究 |

> **松绑的价值**：ST 数据的反卷积参考**不必与 ST 同疾病甚至同研究**，用公开的人源正常组织单细胞图谱即可。这大幅提高 Part 4 的可得性，不要把"必须有配套 sc"设成 ST 的入选条件。

### 6.2 四种串联模式（从数据现状反推可选的链型）

| 模式 | 构成 | 可支撑的叙事 | 课题等级 |
|---|---|---|---|
| **A · 全链（黄金）** | bulk(发现) + 芯片(外部验证) + sc(细胞定位) + ST(空间验证) | 差异基因 → 诊断模型 → 关键基因定位到细胞亚群 → 空间生态位验证 | ★★★★★ |
| **B · bulk 主导链** | bulk(发现) + 芯片(验证) + sc(定位)，无 ST | 模型 + 细胞层面机制，缺空间维度 | ★★★★ |
| **C · 纯建模链** | bulk + 芯片（多队列），无 sc / ST | 大样本诊断/预后模型，统计效能最强，机制薄弱 | ★★★ |
| **D · sc 主导链** | sc(发现) + ST(验证)，bulk/芯片缺失或仅辅助 | 细胞图谱 + 空间共定位，机制类课题 | ★★★★ |
| **E · ST 主导链** | ST 为主 + 公共 sc 作反卷积参考 | 空间生态位、邻域分析、区域异质性 | ★★★ |

### 6.3 成链的"必选件 / 加分件 / 可选件"

| 类别 | 内容 |
|---|---|
| **必选件（Must，缺则链条不成立）** | ① 至少一个 bulk 或芯片作为发现队列（人源优先）<br>② 至少一个**独立外部验证队列**（芯片或另一独立 bulk，不得是同一 BioProject 的拆分）<br>③ 发现队列与验证队列的分组定义可比 |
| **加分件（Should）** | sc 与发现队列同疾病同组织；ST 与 sc 同组织；人鼠双物种均有 |
| **可选件（May）** | 公共 sc 图谱作注释/反卷积参考；鼠源模型做机制验证 |

> **关于外部验证的口径统一**：跨队列做差异基因交叉时，建议统一把分组归约为 **"疾病 vs 正常"** 作为公共分母。治疗应答、分期、时间梯度这类分组在不同研究间定义差异极大，直接交叉会产生大量假阳性。

## 第七部分 · L4 课题反推：从数据特性倒推可选课题

这是筛子的最后一环，**不是先想课题再找数据，而是看手里有什么数据，倒推哪些课题做得成**。

### 7.1 反向选题决策树

```
起点：已收集完的数据集集合
│
├─ Q1. 是否含随访信息（生存时间/状态、进展、复发、应答结局）？
│     ├─ 有 → 可做【预后/进展/应答预测类】课题
│     └─ 无 → 只能做【诊断/分型/机制描述类】，不要硬做预后
│
├─ Q2. 发现队列每组样本量是否 ≥ 20？
│     ├─ 是 → 可上机器学习建模（LASSO/RF/SVM/XGBoost + 外部验证）
│     └─ 否 → 建模不可靠，转向【描述性 + 机制假设类】课题，或小样本稳健方法
│
├─ Q3. 是否有单细胞数据？
│     ├─ 有（同疾病同组织） → 可升级到【细胞亚群定位 / 拟时序 / 细胞通讯】
│     ├─ 有（异组织或公共图谱） → 仅可用作注释参考，不可做疾病特异性推断
│     └─ 无 → 停留在 bulk 层面，或用公共 sc 补一层（需在讨论中声明局限）
│
├─ Q4. 是否有空间数据？
│     ├─ 有（同组织） → 可升级到【空间生态位 / 区域异质性 / 空间共定位】
│     ├─ 有（异组织） → 仅可作方法学参考，不建议写入主线结果
│     └─ 无 → 放弃空间叙事，别为了凑四类硬塞
│
├─ Q5. 人源与鼠源是否都有？
│     ├─ 是 → 加【跨物种保守性验证】，显著提升故事完整度
│     └─ 否 → 单物种亦可，不做跨物种声明
│
└─ Q6. 是否同时有 bulk 与芯片？
      ├─ 是 → 强验证链成立，模型类课题可信度高
      └─ 否 → 需再检索一个独立队列，否则模型类课题不予立项
```

> ⚠️ **关键提醒**：**不要为了凑齐四类数据而硬塞不匹配的数据集**。四类齐全但疾病/组织不匹配的"拼盘链"，其价值低于三类严格匹配的"紧凑链"。Q3/Q4 的"异组织"分支建议直接放弃该维度。

### 7.2 课题模板库（按最低数据配置匹配）

| 课题模板 | 最低数据配置 | 推荐配置 | 核心方法链 |
|---|---|---|---|
| **T1 诊断标志物模型** | bulk(发现) + 芯片(独立验证) | + sc | 差异分析 → WGCNA → LASSO/RF/SVM/XGBoost → AUC/DCA/校准/列线图 |
| **T2 分子分型** | bulk(单一大队列, n≥50) | + 芯片验证 + sc 亚群丰度对应 | 共识聚类 → 亚型差异 → GSVA/免疫-代谢通路 → 亚型临床关联 |
| **T3 关键基因三级串联** | bulk + sc + ST（同疾病同组织） | + 芯片验证 | bulk 差异+WGCNA+PPI → hub gene → sc 定位细胞类型 → ST 看空间表达分布 |
| **T4 细胞图谱与拟时序** | sc（同疾病，donor ≥ 3/组） | + ST 验证 | QC → 整合(Harmony/CCA) → 注释 → 亚群差异 → Monocle/CellRank 拟时序 |
| **T5 细胞通讯** | sc + ST | + bulk 验证配体/受体表达 | CellChat/NicheNet → 通路强度组间比较 → ST 空间共定位验证 |
| **T6 空间生态位** | ST + 公共 sc 参考 | + 配套 sc | 反卷积(Cell2location/RCTD/CARD/SPOTlight) → niche 聚类 → 邻域/共定位分析 |
| **T7 预后/进展预测** | bulk 或芯片（**必须带随访**） | + 独立随访队列 | 单因素/多因素 Cox → LASSO-Cox → 风险评分 → 分层生存 → Nomogram |
| **T8 跨物种保守性** | 人源 bulk/sc + 鼠源 bulk/sc（同疾病同组织） | + ST | 人源发现 → 同源基因转换 → 鼠源独立验证 → 保守模块分析 |
| **T9 代谢/通路重编程** | bulk 或 sc（任一类） | + 多组学交叉 | GSVA/GSEA/ssGSEA → 通路活性评分 → 与表型/亚型关联 |

## 第十部分 · 高频坑清单（采集时必须逐项排查）

| # | 坑 | 后果 | 排查方法 |
|---|---|---|---|
| 1 | **SuperSeries 重复计数** | 样本数被高估，分组混乱 | 检查 GSE 页是否标注 SuperSeries；逐个 SubSeries 单独建卡，不合并计数 |
| 2 | **同一队列拆成多个 GSE** | 误当作两个独立队列做"外部验证"，实为自验证 | 查 BioProject / SRA 编号是否相同；相同则只能算一个队列 |
| 3 | **芯片探针多对一** | 同一基因出现多行，机器学习特征矩阵被污染 | 记录探针→基因聚合策略（均值/最大值），分析前统一处理 |
| 4 | **TPM/FPKM 进 DESeq2** | 结果完全错误 | 检查矩阵值是否为整数；非整数只能用 limma |
| 5 | **单细胞 GPL 当芯片平台** | 错误地去匹配 `hgu133plus2.db` 之类注释包 | RNA-seq/sc/ST 的 GPL 只记录不用于注释；**仅芯片需要注释包** |
| 6 | **批次与分组混杂** | 差异基因全是批次效应 | 查表型里的批次/中心/日期字段，做交叉表看是否完全混杂 |
| 7 | **配对样本未标注** | 统计模型用错，效能被误估 | 查是否有同一 donor 的多次采样/术前术后/左右侧 |
| 8 | **空间图像/坐标缺失** | 无法做空间可视化，课题降级 | 逐项核对 4.4 的关键文件清单 |
| 9 | **临床信息缺失** | 想做预后课题但无随访字段 | 填卡时先确认有无 survival / stage / response 字段，再定课题类型 |
| 10 | **人源数据受控访问** | 下载不了，白检索 | 检查是否指向 dbGaP / EGA；需要申请的直接标为"受控"并在评分中扣至 3 分 |
| 11 | **人鼠基因名转换** | 鼠源基因小写（如 `Tnf`）与人源大写（`TNF`）直接取交集，大量丢失 | 用 `biomaRt::getLDS` 或 `homologene` 做同源映射，别靠大小写转换 |
| 12 | **一个 GSE 内混合多平台** | 合并分析产生严重批次效应 | 检查各 SubSeries 的 GPL 是否一致，不一致必须分开处理 |
