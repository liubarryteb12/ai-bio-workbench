# 出图参考代码库的可参考性与筛选结论（审核第 6 项）

## 一、结论先行

**参考库的价值在「手法与思路」，不在「可直接复用的成品代码」。**

第一梯队 39 条源码全部可读（9-71 行），但抽查 25 条与现有产出重叠的条目后发现：
21/25 没有标题、24/25 没有图例、24/25 没有字号设置。它们是绘图 API 的最小演示，
不是可直接进交付的成品图。

**因此不建议整体移植**，而应按「缺口驱动」选择性借鉴：
只有当现有实现遇到具体问题（某类图没做过、某个视觉手法缺失）时，才去对应条目取手法。

## 三、参考库的结构性优势与劣势

### 优势（值得借鉴的部分）

1. **覆盖广度**：772 条 catalog，涵盖 39 种 plot_type，从基础统计图到高级组合图；
2. **最小示例清晰**：每条 9-71 行，看懂一个手法不需要读几百行工程代码；
3. **有预览图对照**：每条都配 PNG，能直接看效果是否合意；
4. **双语种**：R（circlize/igraph/ellipse）与 Python（matplotlib/seaborn/networkx）各有一批，
   恰好对应我们三线的 R 与 Python 混合现状。

### 劣势（决定了不能直接抄的部分）

1. **不是成品图**：绝大多数条目无标题、无图例、无字号控制，直接抄进交付会违反
   `docs/figure_spec.md`（字号 >= 8pt、图注置轴框外、300 DPI 显式声明）；
2. **无统计口径**：条目只演示「怎么画」，不涉及「画什么统计量、用什么阈值、方向如何定」，
   这部分是我们母版的核心价值所在，参考库提供不了；
3. **通用性优先于领域性**：多数是 seaborn/matplotlib 通用教程形态
   （如「Customizing boxplots appearance」、「Control colors in a seaborn violinplot」），
   与心肌/单细胞/空间转录组的领域语义无直接关系。

## 五、筛选建议

### 不建议做：整体移植 39 条

理由：24/25 无图例、无字号，抄进来要逐条补规范，成本高于自己写。

### 建议做：缺口驱动借鉴

按「我们缺什么」去取，优先级：

| 优先级 | 缺口 | 对应条目 | 借鉴内容 |
|---|---|---|---|
| P1 | **弦图缺失** | rgg_0070 / 0074 / 0075 / 0077（circlize） | 细胞通讯或模块-性状关系的环形可视化，我们目前只有条形与蜂图 |
| P2 | 桑基图 | pgg_0396 | 细胞类型流向（L2 composition 的另一种表达） |
| P3 | 相关性椭圆图 | rgg_0238 / 0240 / 0239 | L1 样本相关矩阵目前是热图，椭圆图更直观 |
| P4 | 2D 密度避让 | pgg_0575 | 火山图点云重叠时的手法（我们当前用 alpha=0.6） |

### 不建议借鉴

- violin / boxplot / histogram / density 的 11 条：均是「外观定制」教程，
  我们的实现已覆盖且更符合交付规范；
- network 4 条：我们的 PPI 网络已用 igraph/graphviz 生产级实现，参考库是演示级；
- wordcloud 2 条：本研究场景无词云需求。

## 六、与「是否参考了参考库」结论的衔接

前面已查明：注册表登记了 source 指向参考库，但 6 个出图脚本**一处都没引用**
（`referencesLibrary=false`，已由 `ops/figure_source_provenance.mjs` 门禁守住）。

本项进一步说明：**即便引用了，能抄到的也主要是「手法」而非「成品」**。
两者合起来指向同一个动作：把参考库定位为**手法词典**（遇到缺口时查），
而不是**代码来源**（整段搬进母版）。注册表的 `source` 字段语义应据此校正为「参考来源」。
