## 二、外部通用框架原型审视 (`agent工作基础项目结构开发`)

在 `D:\00.AIagent\antiworkspace\agent工作基础项目结构开发（hyl工作适用）` 下，开发了一套通用 Agent 自动化工程底座原型（跑通 24 项单元测试，评测准确率 100%）。

### 1. 元宝第一审（调研与对标）结论
- **定级**：「有条件可行，仅作外层薄编排，严禁替换底层 `ops/` 脚本」；
- **优劣势**：自研体系在受限硬件（8GB ARM）、零重型依赖、硬门禁审计下比 LangGraph/MetaGPT 更轻量可控；但在动态图规划与生态兼容性上较弱；
- **30 项资产瘦身清单**：
  - **保留核心**：SPEC / AGENT / SCOPE / router / dispatcher / schema 防火墙 + tool_executor / loop_controller / hooks / tasklist / adr / skills-stable；
  - **合并内聚**：GLOSSARY 并入领域 TERMS；三本台账合并为单一结构；checkpoint + state_machine 合并；
  - **剔除降级**：剔除独立 personas 目录（改内联）、剔除 gap_analyzer（移出关键调度路径）、剔除 version_controller（并入 manifest）；
- **P0 硬红线**：融合侧**零新增顶层目录**，全部资产按既有 `ops/`, `docs/`, `tests/` 结构嵌入。

### 2. DeepSeek 第二审（批判性代码审计）揭示的 5 大盲区
DeepSeek 结合本地代码推演，指出元宝初稿存在的致命悬空：
1. **Gateway 失败语义悬空**：网关若在崩溃/超时时默认跳过校验，安全网关即退化为装饰品。**判定：必须默认 Fail-Closed (DENY)**；
2. **`tasklist.py` 降级分支代码缺失**：元宝宣称“P1 失败走降级分支”，但代码无降级字段，下游任务若依赖 P1 会陷入永久死等。必须引入显式 `accept_degraded` 声明；
3. **台账 verifier 缺乏执行力**：若 `verifier.command` 无自动化门禁触发机制，台账必沦为技术债。必须像 `router_gate` 绑定 REJ 一样，硬约束 `enforced_by` 存在且可执行；
4. **双语校验回滚契约空白**：Node 放行后 Python 计算 6 分钟失败时，若无原子落盘，残缺中间件会污染环境；
5. **IPC 协议漏洞**：跨 Node/Python 与 Win/Linux 严禁走 stdio 管道（高频长 JSON 必死锁），必须走**「临时参数文件 + 退出码三态」**。
