## 三、典型历史踩坑记录复盘（PIT 精选）

### 1. PIT-001：比例尺自检循环自证陷阱
- **事故场景**：早期在测试比例尺绘制时，自检代码直接从解析参数计算 `actual = (x + bar) - x`；
- **踩坑教训**：该表达式在代数上恒等于 `bar`。当 Matplotlib 布局调整导致坐标轴被压扁、实际显示的比例尺缩水 5.4% 时，该自检依然通过；
- **根治修法**：自检必须读取真实渲染在屏幕上的图形线元 `line.get_xdata()`，经过真实 `transData` 矩阵转换后计算像素跨度，彻底打破循环自证。

### 2. PIT-002：Space Ranger `spot_diameter_fullres` 表观直径浮动
- **事故场景**：误把 Space Ranger 估计的表观光斑直径当作物理标定基准；
- **踩坑教训**：光斑表观大小随染色聚焦波动，5 个样本波动达 3.6%，导致 500 µm 比例尺系统性偏长；
- **根治修法**：必须改按载玻片物理六角晶格中心距（100.0 µm / 内部点第一壳层中位 132.0 px = 0.757554 µm/px）做硬基准。

### 3. PIT-003：Windows 原生 OpenSSH 缺 SystemRoot 静默 255
- **事故场景**：在 Node 子进程中调用原生 `ssh` 时进程瞬间以退出码 255 退出，无任何错误输出；
- **踩坑教训**：Windows OpenSSH 底层加载 Winsock 依赖 `%SystemRoot%` 环境变量；
- **根治修法**：在所有本地子进程出口注入 `childEnv` 补齐环境变量。

### 4. PIT-004：Python 临时脚本模块遮蔽 (Shadowing)
- **事故场景**：在工作区 `.tmp/` 下临时创建了名为 `platform.py` 的测试脚本，随后导致所有 Python 脚本在 `import anndata` 时崩溃；
- **踩坑教训**：当前目录下的 `platform.py` 覆盖了 Python 标准库中的 `platform` 模块；
- **根治修法**：临时测试脚本一律命名为带有特殊业务前缀的名称（如 `probe_platform_test.py`），严禁使用标准库同名文件名。

## 四、接手人十条日常开发防雷守则

1. 每次修改代码后，**先跑 `node ops/run_all_gates.mjs --skip-tests`**，12 秒确认基础门禁全绿；
2. 准备提交代码前，**必跑全量 `node ops/run_all_gates.mjs`**，确保 1823 条测试与基线完全一致；
3. 严禁使用 Windows CRLF 行尾修改任何 `src/*/scripts/` 下的 Linux 母版；
4. 涉及远端执行的代码，必须通过 `ops/06_deploy_scripts.ps1` 走正门同步，禁止私自 SSH 上机乱改；
5. 编写测试用例必须使用 `tests/support/test_tmp.js` 获取临时目录，严禁在系统公共路径硬编码临时文件；
6. 编写文档与报告严禁使用 em dash（`—`），一律使用标准逗号、冒号、括号或句号；
7. 涉及空间切片计算时，严格执行晶格 100 µm 标定公式，严禁改回 `spot_diameter_fullres`；
8. 严禁在交付报告正文或图注中出现任何开发机、服务器、容器或内部路径名称；
9. 任何已否决设计（REJ）或新增台账条目，必须绑定真实门禁，且 `expires_at` 严格 $\le 180$ 天；
10. 永远保持三线隔离意识：线 1、线 2、线 3 是平行宇宙，严禁跨线拷贝数据或互相依赖。
