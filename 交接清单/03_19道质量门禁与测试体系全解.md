## 二、变异测试反证哲学（Mutation Testing）

### 1. 为什么必须有变异反证？
传统测试只证明**“当代码正确时，测试是绿色的”**。但它无法排除：
- 断言被写成恒真（如 `assert.ok(true)` 或 `dxb - dxa === bar` 恒等式）；
- 门禁逻辑存在静默跳过漏洞，无论注入什么坏数据都默默放行。

**变异反证原则**：**“只有当防线被破坏时必然变红，这道防线才被证明真正存在。”**

### 2. 13 条现存变异反证清单 (`escaped === 0`)
变异门禁分为 `infra`（底座防线）与 `behavior`（业务规则防线）两层：

```text
ops/mutation_gate.mjs (7 条防线注入):
  MUT-01 [infra]    故意放宽 clean_workspace 白名单 -> 必须抓出白名单漂移
  MUT-02 [infra]    故意伪造 metrics_sync 实测用例数 -> 必须被基线比对拦截
  MUT-03 [infra]    篡改 actions.jsonl 历史记录某行哈希 -> 台账门禁必红
  MUT-04 [infra]    向测试注入未白名单的跳过理由 -> skip_reason 门禁必红
  MUT-05 [behavior] 在 .sh 母版中注入 Windows CRLF 行尾 -> static_gate 必红
  MUT-06 [behavior] 篡改某 Ready 模板预览图单个像素 -> ready_matrix 必红
  MUT-07 [behavior] 声明 DERIVED 却从不调用参考库函数 -> 溯源门禁必红

ops/q3q2_mutation_gate.mjs (6 条状态与路由变异注入):
  MUT-08 [behavior] 破坏路由最长命中词决胜逻辑 -> 黄金集评测必红
  MUT-09 [behavior] 路由表放行不存在的幽灵 Mod ID -> router_gate 必红
  MUT-10 [behavior] 篡改 SCOPE.md REJ 绑定至不存在文件 -> router_gate 必红
  MUT-11 [infra]    状态机非法转移 (COMPLETED -> RUNNING) -> 状态机断言必红
  MUT-12 [infra]    非原子状态文件写入断电模拟 -> 快照校验必红
  MUT-13 [infra]    缺少必要状态字段的任务提交 -> 任务构建器必红
```

每次门禁输出必须呈现：`分层 infra=7/7 behavior=6/6｜escaped 两层均为 0`。任一变异存活即视为重大安全隐患。

## 三、测试套件体系架构（212 测试文件 / 1823 测试用例）

测试代码集中于 [`BioanalysDesktop/tests/`](../BioanalysDesktop/tests/)，由 Node.js 原生 `node:test` 驱动，零外部 Jest/Mocha 框架依赖。

### 1. 核心测试分类
1. **进程与安全接缝测试**（`proc.test.js`、`audit.test.js`）：测白名单程序拦截、跨线越界命令拦截、Windows childEnv 补齐；
2. **任务状态机与编排测试**（`task_fsm.test.js`、`task.test.js`、`run.test.js`）：测任务生命周期合法转移、SSH 派发包装、断点续传；
3. **声明式路由与边界测试**（`router_eval.test.js`、`router_gate_contract.test.js`）：用 27 条真实业务黄金集评测命中准确率（100% 27/27）；
4. **空间图件与物理标定契约**（`figure_scalebar_contract.test.js`、`spatial_pitch_algorithm_contract.test.js`）：断言晶格 100 µm 标定、延迟绘制、护栏带；
5. **商业机密级脱敏契约**（`report_redaction_contract.test.js`）：断言交付报告正文绝不泄露机器名与基础设施路径。

### 2. 唯一允许的条件跳过（SKIP 白名单）
当前全量 1823 个测试中，仅有 **1 个合法跳过**：
- **用例名**：`bridge_stage` 跨语言校验测试中的坏 h5ad 注入用例；
- **跳过条件**：当 Windows 宿主机未安装科学计算 Python 栈（缺 `anndata` 模块）时触发；
- **白名单标识**：`HOST_MISSING_PYTHON: 本机无法加载 anndata 模块`。
- **其他任何环境**：只要满足依赖，全量用例必须真跑全绿。严禁在代码中新增无白名单理由的 `t.skip()`。

## 四、门禁维护与扩展纪律

1. **新增门禁规则**：
   - 必须以纯 Node ESM 编写于 `ops/<name>_gate.mjs`；
   - 耗时超过 5 秒的门禁必须在 `ops/run_all_gates.mjs` 中标记 `slow: true`；
   - 涉及远端设备的门禁，当设备离线时必须以 `exitCode 2` 表达有状态 SKIP，严禁隐瞒跳过。
2. **修改既有门禁**：
   - 必须同步更新 `ops/mutation_gate.mjs` 或 `ops/q3q2_mutation_gate.mjs` 中对应的变异注入点，确保破坏测试同步生效。
