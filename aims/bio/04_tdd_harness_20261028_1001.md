## 零、 给项目主理人的“大白话”工程词典（你说的概念非常准，这里为你补全拼图）

你提到的 **TDD（测试驱动开发）** 和 **Harness（测试台架/夹具）** 正是世界顶级软件工程中最核心的两个词！作为项目主理人，你不需要自己手写底层代码，但你需要用下面 **8 把工程尚方宝剑** 来指挥和验收 AI 的工作：

| 专业工程术语 | 大白话解释（像造汽车/插卡带一样理解） | 在咱们这个生信工作台里具体管什么？ |
| :--- | :--- | :--- |
| **1. TDD（测试驱动开发）**<br>*Test-Driven Development* | **“先立验钞机，再印钞票”**。绝不允许 AI 先写业务代码再补测试；必须**先写一段会报错的测试（红灯 Red）**，再写刚好能通过的代码（绿灯 Green），最后优化结构（重构 Refactor）。 | 改箱线图横线、补 16 个图模板映射前，先写死“如果 `tip.length != 0` 就报错”的测试，逼着 AI 把代码改对。 |
| **2. Test Harness（测试台架/夹具）** | **“汽车碰撞实验室的假人和跑步机”**。红米 K40 跑一次单细胞要 40 分钟，平时改一行前端代码不可能每次都连手机真跑。Harness 就是一套**仿真沙箱底座**，能模拟手机发烧、断网、内存爆表、门户并发上传，在 5 秒内把极端情况测完。 | 造 4 套核心台架：① 模拟 K40 算力台架（Mock SSH）；② R/Python 桥接台架；③ 27 入口出图台架（Plot Matrix Harness）；④ 门户-工作台 Sync 故障注入台架。 |
| **3. 静态架构门禁（Arch Linter & AST）** | **“装修前的承重墙扫描仪”**。不用运行程序，直接扫描代码结构：看有没有哪个业务卡带（Mod）偷偷去改了宿主微内核（Core），或者注释里写了 `# Rscript` 导致误判。 | 守护“零触碰宿主（Zero-Touch Host）”铁律：扫描 `src/core/` 是否出现 `line1` 等业务词，扫描 `src/mods/mod-a` 是否偷连 `mod-b`。 |
| **4. 契约测试（Contract & Parity Test）** | **“插头与插座的游标卡尺”**。8080 门户、18787 工作台、K40 手机容器三个地方各跑各的，怎么保证它们对“20 条肿瘤黑名单”、“14 种文件格式”、“图模板字段”理解一模一样？靠契约测试死死咬住。 | 防治 G1/G2 缺口：保证 `figure_templates.json` 里写的产出文件名，跟 K40 脚本真正在磁盘上生成的文件名 100% 对得上。 |
| **5. 性质测试与模糊测试（Property & Fuzzing）** | **“雇一群猴子乱按键盘”**。普通测试只测正常输入（比如上传正常基因表）；Fuzzing 专门喂脏数据：带 `../` 的黑客路径、超大 25GiB 分片、空文件、中文乱码列名、基因名带特殊符号（如 `PD-1` vs `GPD1`）。 | 检查系统会不会因为客户传了一个奇葩 Excel 或狂点 100 次“同步”按钮而直接崩溃或写穿手机闪存。 |
| **6. 混沌工程与故障注入（Chaos & Fault Injection）** | **“故意拔电源、泼冷水演练”**。在程序跑得正欢的时候，故意断开 ADB 数据线、故意让 K40 温度报 96℃、故意把磁盘剩余空间塞到 19%，看系统能不能按规定暂停、报警、切换备用节点，而不是卡死在“假装运行中（running）”。 | 验证 P-26（脱离本机进程树）、P-29（防并发 SSH 崩容器）以及交付四道闸拦截变 `blocked` 的真实可靠性。 |
| **7. 黄金主本与快照对账（Golden Master & Bit-Exact）** | **“高清防伪底片比对”**。生信分析最怕“今天跑出 50 个差异基因，下周升级了包跑出 48 个”。固定死随机种子 `seed=20261013` 和标准输入（Fixture），每次跑完比对 17 位小数精度和图片像素特征。 | 解决 G3 缺口：27 个出图代码入口，每一个都必须有固定输入、固定种子、非空白像素方差校验和 SHA256 金标准档案。 |
| **8. 变异测试（Mutation Testing / 测测试的测试）** | **“故意放个假小偷，看保安抓不抓”**。很多时候 949 个测试全绿，是因为测试写得太水（假绿灯）。故意把代码里的 `>= 20%` 改成 `>= 10%`，如果测试还是绿灯，说明这个测试是废的！ | 专门揪出“写了测试但没真正断言核心逻辑”的虚假安全感。 |

### 1.2 【第二代：潜伏暗雷与边界 Bug（Latent / Edge-Case Bugs : 一压测就会爆）】
> 这些问题平时单人顺畅操作时不一定会报错，但在真实客户使用、大文件上传、长任务并发或断网重连时极易暴雷：

1. **L-01：JSONL 追加写并发撕裂（Log Corruption under Concurrency）**
   * **暗雷机理**：`ops/sync_daemon.ps1`、18787 工作台 API、脚手架脚本可能在同一毫秒向 `con_hf/ledger/actions.jsonl` 或项目 `ledger/*.jsonl` 追加一行。如果没有文件锁或原子追加保护，两行 JSON 会交错拼成一行非法 JSON，导致 `ops/ledger_indexer.py` 解析整本台账崩溃。
   * **排查与防御**：在 `LedgerStore` Harness 中模拟 20 个并发进程同时追加 100 行，强制要求每行写入使用 OS 级 `O_APPEND` 原子单次 `write()`，且读取器具备**单行容错隔离（壞行告警不崩盘）**能力。
2. **L-02：分片上传“僵尸预留”死锁（Orphaned Quota Reservation）**
   * **暗雷机理**：`POST /api/upload/init` 预留了 `reservedBytes`（比如客户声明上传 4.5GiB 文件），并且在 10 分钟活跃保护期内受保护。如果恶意或误操作客户端连续发起 5 次不同文件名的 `init` 却不传 `chunk`，20GiB 配额瞬间被占满，正常客户全部收到 `507 Insufficient Storage`。
   * **排查与防御**：在 `QuotaGuard` Harness 中测试“只 init 不传 chunk”攻击，强制规定：**单项目未完成会话数上限 $\le 3$ 个**，且 `0 chunk` 会话的保护期缩短为 **90 秒**。
3. **L-03：Windows 与 Linux 路径分隔符及大小写混毒（CRLF / Path Slash Poisoning）**
   * **暗雷机理**：本地是 Windows 11（反斜杠 `\`、大小写不敏感、CRLF 换行），远端是 K40 Ubuntu（正斜杠 `/`、大小写敏感、LF 换行）。一旦生成的 `adapt_<fig_id>.R` 或 `sync_manifest.json` 混入 `
` 或 `local_projects\PRJ_xxx`，上传到 K40 执行 `bridge_guard.sh` 时第一行 `#!/usr/bin/env bash
` 就会报 `bad interpreter: No such file or directory`。
   * **排查与防御**：建立 **Cross-OS Normalization Gate**:所有落入 `src/`、`ops/`、`figures/adapt/` 的脚本和 JSON 路径键，静态扫描一旦发现 `
` 或未归一化的 `\` 立即阻断。
4. **L-04：K40 `setsid nohup` 孤儿进程与重复派发（Double-Dispatch Zombie）**
   * **暗雷机理**：当 `l2_ko_scrna`（虚拟敲除，耗时约 35 分钟）正在 K40 容器后台跑时，如果本地 18787 重启或 SSH 闪断重连，编排面若未先检查远端 `/mnt/ssd/bio_data/system_logs/<task_id>_ledger.json` 的 `running` 锁与 PID 存活状态，直接二次下发同一个任务，两个 `scTenifoldKnk` 同时跑会瞬间撑爆 7.5GB 内存导致双双 OOM 暴毙（且违反 P-29）。
   * **排查与防御**：在 `compute-engine` 增加 **远端幂等任务锁（Idempotent Remote Lockfile）**，下发前先查远端 lock 与 `status=="running"`，若已在跑则直接挂载轮询（Re-attach）而非重复拉起。
5. **L-05：R / Python 桥接时的基因名自动转义污染（`make.names` Mutation）**
   * **暗雷机理**：R 语言读取含有连字符的基因名（如 `HLA-DRA`、`MT-CO1`、`NKX2-1`）时，若未显式设置 `check.names = FALSE`，R 会静默把 `-` 改成 `.`（变成 `HLA.DRA`）。等桥接回 Python 或与离线 STRING 库比对时，这批核心基因全部丢失！
   * **排查与防御**：在 `verify_bridge_checkpoint.py` 四项断言的第 ① 项（Symbol 完整性）中，专门注入含 `-` 和数字开头的测试基因，断言跨语言前后 Symbol 字符 **100% 零变形**。

### 1.3 【第三代：未来演进与规模化隐患（Future Scalability & Maintenance Risks）】
> 当未来新增第 4 条分析线（如代谢组/蛋白组）、将 65 个待采集图型补齐、或接入多台备用计算节点时的前瞻性防御：

1. **F-01：“零触碰宿主（Zero-Touch Host）”退化腐败风险**
   * **隐患**：后续开发人员为了图省事，又在 `server/index.js` 或 `App.tsx` 里写 `if (line === 'line4_metabo')` 硬编码分支，破坏微内核卡带架构。
   * **防御**：建立 **热插拔编译测试（Mod Hot-Unplug Harness）**:在 CI 中随机移走一个 `src/mods/mod-*` 目录，验证宿主依然 100% 编译通过且五维自检不崩。
2. **F-02：65 个待采集 Bizard 图型入册时的依赖污染与许可证/字体风险**
   * **隐患**：未来补齐 65 个图型源码时，可能引入需要 X11 图形界面、商业字体（Arial/Helvetica 缺失导致中文变方框 `□□□`）或在 ARM64 上编译失败的 R 包。
   * **防御**：在 Plot Matrix Harness 中内置 **CJK 字体渲染断言**（统一强制 `Noto Sans CJK SC` / `wqy-microhei`）与 **无头 Cairo/Agg 沙箱预检**，新图型不通过三层递进验证绝不允许将 `deps_status` 标为 `ready`。
3. **F-03：多节点算力池（Failover）状态脑裂（Split-Brain on Failover）**
   * **隐患**：未来主节点 K40 95℃ 高温熔断切换到备用节点时，前序步骤（Step 1~5）的数据还在主节点 `/mnt/ssd/bio_data/projects/` 上，备用节点没有中间产物，直接从 Step 6 跑必败。
   * **防御**：在 `compute-engine` 规定故障转移协议:切换节点前必须以本地 `local_projects/<project>/data/` 已回搬的最新检查点（Checkpoint）为准，先向备用节点增量同步前序检查点产物，再续跑后续步骤。

## 二、 专业 TDD（测试驱动开发）全流程设计规范

为了让你和 AI Agent 彻底告别“先乱改代码、报错了再打补丁”的低效循环，全平台强制实施 **「五步严格 TDD 循环（Red → Green → Refactor → Verify → Ledger）」**。

### 2.1 五步 TDD 标准作业程序（SOP）

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ Step 1 [RED 先写失败测试]                                                    │
│ 根据 aims 总目标与 aims 落地，先在 BioanalysDesktop/tests/ 写测试。          │
│ 运行 npm test --prefix BioanalysDesktop，新增测试先报红再转绿。              │
└──────────────────────────────────────┬───────────────────────────────────────┘
                                       ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ Step 2 [GREEN 编写最小实现代码]                                              │
│ 严格在 WIP=1 锁定的独占文件域（write_scopes）内修改业务代码或 R/Python 脚本  │
│ 再次运行测试，直到刚才报红的测试变绿（PASS），且原有 949 条测试零回归失败。   │
└──────────────────────────────────────┬───────────────────────────────────────┘
                                       ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ Step 3 [REFACTOR 微内核解耦重构]                                             │
│ 检查代码是否违反微内核三层单向依赖、是否残留硬编码路径或魔法数字，清理干净。  │
└──────────────────────────────────────┬───────────────────────────────────────┘
                                       ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ Step 4 [HARNESS & K40 实机/台架联调]                                         │
│ 若涉及生信脚本或出图，运行 Plot Matrix Harness 或 K40 真机验证，获取 SHA256。 │
└──────────────────────────────────────┬───────────────────────────────────────┘
                                       ▼
┌──────────────────────────────────────────────────────────────────────────────┐
│ Step 5 [LEDGER 台账打卡与 WIP 解锁]                                          │
│ 将测试命令、通过断言数（如 953/953）、产物 SHA256 写入 aimstodolist 与 JSONL  │
│ 解除当前任务 WIP=1 锁，方可进入下一个原子任务。                              │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 针对当前 G1~G6 缺口的 TDD 实战用例设计（可直接落盘到 `BioanalysDesktop/tests/`）

我们在动手修 G1~G6 之前，**先写好下面这个守门员测试文件（当前等价落点：`BioanalysDesktop/tests/wp33_figure_adapt.test.js` 与 `BioanalysDesktop/tests/figure_templates_parity.test.js`）**。它们分别覆盖 G2 图模板派生执行闭环与 G1 图模板字段契约：

```javascript
// 当前等价文件路径：BioanalysDesktop/tests/wp33_figure_adapt.test.js
// 当前等价文件路径：BioanalysDesktop/tests/figure_templates_parity.test.js
// 作用：专门针对 PROJECT_REPORT.md 中 G1、G2、G4、G6 缺口的 TDD 先行红灯测试套件

import test from 'node:test';
import assert from 'node:assert/strict';
import fs from 'node:fs';

const ROOT = process.cwd();

// 【TDD-01：猎杀 G4 缺口 : 箱线图显著性标注严禁存在 tip.length > 0】
test('[TDD-G4] 箱线图正式版与 R4.5.3 兼容版必须锁死 tip.length = 0 (纯水平横线)', () => {
  const boxplotFiles = [
    path.join(ROOT, 'reference/05.可参考出图代码/L1_基础统计图/L1_boxplot_code.R'),
    path.join(ROOT, 'reference/05.可参考出图代码/_meta/R453_compat/L1_boxplot_code.R')
```

## 三、 五大专业测试台架（Test Harness）架构设计

为了在不插手机、或者不跑满 40 分钟长任务的情况下，也能随时对系统进行高强度体检，我们在 `src/engines/` 下设计 **5 台专业测试台架（Test Harnesses）**：

### 3.1 台架一：微内核插座与零触碰宿主台架（`Microkernel & Zero-Touch Harness`）
* **当前等价实现**：`BioanalysDesktop/tests/manifest.test.js` + `BioanalysDesktop/tests/manifest_mod_form.test.js` + `BioanalysDesktop/tests/aims_drift_guard.test.js`（微内核 manifest 契约与架构漂移守卫）+ 顶层 `src/core/`（`CapabilityBus.ts`、`ModLoader.ts`、`SlotManager.ts`）
* **解决什么问题**：防止未来代码腐败，防止模块之间私拉乱接电线（横向 `import`），防止宿主 `src/core/` 写死业务词。
* **四大自动化检验动作**：
  1. **宿主无知性扫描（Host Agnosticism Scan）**：静态扫描 `src/core/` 下所有文件，一旦出现 `line1`、`line2`、`line3`、`wgcna`、`scTenifoldKnk`、`volcano` 等具体业务字样，立即判 `FAIL`。
  2. **跨卡带绝缘扫描（Cross-Mod Insulation Scan）**：解析 `src/mods/mod-*/` 下所有 `.ts/.js` 的 AST `import` 语句，断言任何 `mod-A` 绝对不包含指向 `../mod-B/` 的导入（跨模块通信必须 100% 走 `CapabilityBus`）。
  3. **卡带热拔插仿真（Hot-Unplug Simulation）**：在内存虚拟文件系统中依次屏蔽 `mod-line1-bulk`、`mod-figure-templates` 等任意单个卡带，启动 `ModLoader` 与 `SlotManager`，断言系统启动耗时 `< 500ms`、零未捕获异常、缺失插槽返回优雅降级占位符。
  4. **契约完整性校验（Manifest Contract Check）**：对所有扫描到的 `manifest.ts` 校验 `id`、`stageOrder`、`enginesRequired`、`dbStores` 类型合法性。

### 3.2 台架二：K40 容器算力与长任务混沌仿真台架（`K40 Compute & Chaos Harness`）
* **当前等价实现**：`BioanalysDesktop/tests/node_failover.test.js` + `BioanalysDesktop/tests/selfcheck.test.js` + `BioanalysDesktop/tests/p29_ssh_flow_guard.test.js` + `BioanalysDesktop/tests/wrapper_running_marker.test.js` + `ops/k40_adb_forward.ps1`
* **解决什么问题**：无需每次都折腾真机红米 K40，就能在本地 3 秒内模拟 K40 高温 96℃、SSH 断连、FUSE 分区误挂载、磁盘低于 20%、并发 SSH 触发 proot abort 等极端灾难。
* **五大故障注入（Fault Injection）场景**：
  1. **场景 A（高温熔断与冷却续跑测试）**：仿真 SSH 返回 `/sys/class/thermal/thermal_zone0/temp` 为 `96000`（96℃），验证：① 18787 五维自检第 3 维立即变 `fail`；② 新任务自动触发 Failover 路由至备用节点（或进入 `sleep 30` 冷却循环）；③ 随后注入 `74000`（74℃），验证冷却循环自动解除并拉起进程。
  2. **场景 B（假绿灯猎杀测试）**：仿真 SSH 超时（退出码 255）或返回空字符串 `""` 或缺失 `END` 标记，验证 `BioanalysDesktop/server/proc.js` 的 `runSshStrict` 100% 抛错判为 `unknown`（`all_pass = false`），绝不出现“把空输出当成 0 错误判 `pass`”的假绿灯。
  3. **场景 C（P-29 反并发风暴测试）**：连续向算力引擎发起 5 个任务请求，验证台架拦截器证实：① 同一时刻 SSH 活跃连接数 $= 1$；② 状态轮询间隔严格 $\ge 60	ext{s}$；③ 任何含 `find /`、`ps aux`、`grep -r` 的命令在发送前被本地守卫直接掐断。
  4. **场景 D（FUSE 与存储红线测试）**：仿真 `df -T` 返回 `fuse` 或 `df -P` 剩余空间 `18%`，验证任务提交接口与报告生成接口双双返回拦截码。
  5. **场景 E（重复派发防 OOM 测试）**：仿真远端 `<task_id>_ledger.json` 处于 `status: "running"`，验证编排面重启后执行 Re-attach 挂载轮询，绝不二次执行 `setsid nohup`。

### 3.3 台架三：27 入口脚本级出图验证台架（`Script-Level Plot Matrix Harness` : 专治缺口 G3/G4）
