# AI 辅助生信分析工作台架构与执行总纲（v2.4 实战对齐版）

---

## 一、 架构拓扑与三大铁律

### 1. “云-端”解耦架构拓扑

* **本地交互层（零算力消耗）**：本地终端仅运行 Web 浏览器（访问工作台四大界面）或轻量级 IDE（VS Code Remote-SSH 直连服务器）。本地不保留代码副本、不参与任何计算。
* **网络传输与自愈层**：SSH 隧道加密传输控制流与代码流；HTTP/S（配合外网穿透与 Token 鉴权）支持远程建项、大文件分片上传与结果预览；本地通过 `00_link_check.ps1` 实现断链自动重连（`adb forward` 重建 + `monkey` 自动拉起 Termux 服务）。
* **远程计算与存储层（红米 K40 核心底座）**：
* **物理硬件**：红米 K40（骁龙 870 八核处理器 + **12GB LPDDR5 运存** + **原生 UFS 3.1 高速闪存**，配合外置风冷与充电限流/旁路供电）。
* **系统与容器层**：Android (Termux 底座，**无 Root 约束**) + Ubuntu (ARM64) 容器环境，通过 Conda/R 独立环境实现三条分析线的依赖隔离。
* **长任务守护层**：所有计算任务强制通过 `nohup` / `tmux` 后台守护运行，基于每步退出码（`exit 0`）与产物校验实现断点续跑。



### 2. 三大不可逾越的执行铁律

1. **非肿瘤、非免疫浸润专精原则**：全流程专精非肿瘤领域（心脑血管、神经退行、代谢、纤维化、发育等），不主动加入临床生存预后、肿瘤免疫浸润、药物敏感性预测等未要求内容；建项时前后端各拦一次肿瘤/免疫相关词汇（前端即时提示 + 后端权威拦截）。黑名单规格正本为 §三.1 模块 A 的 8 条（2026-10-21 裁定收敛），权威实现 `BioanalysDesktop/server/tumor_blacklist.js`，提交台 `portal/index.html` 内的正则只是副本，两侧一致性由 `BioanalysDesktop/tests/tumor_blacklist_parity.test.js` 把守。
2. **三条平行分析线物理与逻辑硬隔离原则**：
* **线 1**：GEO Bulk 线（`line1_bulk`）
* **线 2**：单细胞转录组 + 虚拟敲除线（`line2_scrna`）
* **线 3**：单细胞空间转录组 + 虚拟敲除线（`line3_spatial`）
* **隔离红线**：三条线不互相取参考、不合并、不跨线验证。**虚拟敲除绝不是第四条独立线**，而是线 2（第 10 步）和线 3（第 9 步）各自的末端模块。


3. **R / Python 线内最优分工与单向桥接原则**：仅允许同一条线内部按工具优势混用 R 与 Python，严禁跨线混用。固定主语言、包版本与随机种子（`seed = 20261013`），严格控制语言切换次数（线 1 步骤 1-4 全 R，步骤 5-8 切 Python 1 次单向切换；线 2 切换 2 次；线 3 切换 1 次）。每次跨语言转换必须通过**桥接四项断言检查点**（基因名 Symbol 完整性、矩阵行列方向与稀疏性、细胞 Barcode 顺序、降维/空间坐标保留），由 `ops/verify_bridge_checkpoint.py` 自动执行。

## 二、 服务器端物理隔离目录结构规范

统一锚定手机原生 Linux 分区路径 `/mnt/ssd/bio_data/`（经 `df -T` 只读校验为原生 `ext4`/`f2fs`，严禁写入 `/sdcard` 或任何 `fuse` 模拟层）：

```text
/mnt/ssd/bio_data/                  # 手机原生 UFS 3.1 高速分区根目录 (ext4/f2fs)
├── ops/                            # 平台级算力削峰、存储门禁、桥接校验与守护脚本
│   ├── check_storage_and_isolation.sh
│   ├── run_throttled_task.sh
│   └── verify_bridge_checkpoint.py
├── projects/                       # 【数据面唯一入口】先按项目、再按线物理隔离
│   └── <项目>/                      # 项目 id，如 PRJ_20261020_DKD_bulk / default
│       ├── project.json            # 建项契约（分组/样本/数据源/交付期望）
│       ├── line1_bulk/             # 【线1】GEO Bulk 线独占物理目录
│       │   ├── raw_data/           # 原始 GEO 矩阵 / 平台 GPL 注释文件
│       │   ├── processed/          # 物理拆分为 train/ 与 val/ 子目录（严防数据泄漏）
│       │   ├── results/            # DEG/WGCNA/PPI/LASSO+RF/共表达/SHAP/聚类/外部验证结果
│       │   └── figures/            # 300 DPI 图件（出图规范见 §五）
│       ├── line2_scrna/            # 【线2】单细胞转录组 + 虚拟敲除线独占（同上四层）
│       └── line3_spatial/          # 【线3】空间转录组 + 虚拟敲除线独占（同上四层）
├── bin/                            # 各线可执行与母版脚本落点（bin/<line>/）
├── envs/                           # 各线独立环境与锁文件（envs/<line>/）
├── public_references/              # 公共标准参考图谱库（如 Allen Brain Atlas 等公共单细胞参考）
│   └── (铁律：仅供线内合规调用，严禁从 line2 提取数据放入此处供 line3 反卷积使用)
└── system_logs/                    # 自动化 JSON 台账、任务标准输出日志与 SHA256 校验记录

```

**合法根与归属口径（单一事实源：`BioanalysDesktop/server/ledger.js` 的 `analyzePath` / `inspectTaskPath`）**：

* 任务输入/输出只认四种形态：① `/mnt/ssd/bio_data/projects/<当前项目>/...` 下任意子路径；② `/mnt/ssd/bio_data/public_references/...`（只读，仅可作输入）；③ 迁移前历史三线形态 `/mnt/ssd/bio_data/<line>/...`（仅台账审计兼容，提交侧不放行）；④ **裸相对文件名**（任务脚本先 `cd` 到 `<项目>/<线>/processed/`，由 shell 解析）。
* `system_logs/` 由台账通道独占写入，禁止作为任务输入或输出；`public_references/` 禁止作为输出目录。
* 相对路径只接受**裸文件名**与 **`projects/<项目>/...`** 两种形态；`processed/x.tsv` 这类「目录 + 文件名」在提交层直接 400（报「相对路径缺少合法根」），避免 cwd 歧义。
* 项目段比对**大小写敏感**；任何含 `..` 的路径在归一化之前一律拒绝。
* 提交层（`POST /api/tasks/submit`）、台账审计（`classifyPath` / `auditLedgerEntry`）、文件访问守卫三处共用同一套合法根，禁止各自维护副本。

## 三、 工作台前端与服务端四大视图界面设计

### 1. 独立页面：新建项目向导页（Project Onboarding Portal）

允许外网安全访问，所有表单操作与后端建项配置 `project_manifest.json` 1:1 对齐：

* **模块 A（项目基本信息与非肿瘤合规拦截）**：填写项目名称、项目描述、物种（`Homo sapiens` / `Mus musculus` / `Rattus norvegicus`）、非肿瘤研究领域下拉框、具体疾病名称（前端内置正则黑名单 + 后端建项前复核双保险；命中即红字拦截并禁止提交）。
  * **黑名单确认清单（2026-10-21 用户裁定：以本清单 8 条为规格正本，`BioanalysDesktop/server/tumor_blacklist.js` 逐条实现）**：
    - 英文 5 条：`cancer`、`tumor`、`carcinoma`、`glioma`、`immune infiltration`（正则 `immune\s*infiltration`，允许词间空白）；
    - 中文 3 条：`肿瘤`、`癌`、`免疫浸润`；
    - 全部 `i` 大小写不敏感；中英文按子串匹配（如"癌"命中"癌变/致癌物"、"非肿瘤"命中"肿瘤"，属预期拦截）。
  * **出处与沿革**：上述 8 条为 aims 早期列举原文（2026-10-21 按 S21 侦察报告 `con_hf/dispatch/S21_scout_workbench_gaps.md` 疑点 h 逐字复核）。2026-10-20 曾裁定以 `tumor_blacklist.js` 当时自行扩充的 27 条为规格正本；2026-10-21 用户裁定收敛回本清单 8 条，理由是那 19 条扩充（`tumour`、`sarcoma`、`lymphoma`、`leukemia`、`leukaemia`、`melanoma`、`immune checkpoint`、`PD-L1`、`CTLA-4`、`oncogene`、`免疫检查点` 等）没有规格条文依据，违反项目铁律"只按规格中经确认的黑名单和校验规则实现拦截，不要自行扩充规则"。**后续增删规则必须同时改本清单与 `tumor_blacklist.js`**，不允许任一侧单方面漂移。
  * **已知边界**：收敛后英式拼写 `tumour`、`sarcoma`、`lymphoma`、`leukemia/leukaemia`、`melanoma`、`immune checkpoint`、`PD-L1/PD1`、`CTLA-4`、`oncogene`、`免疫检查点` 不再单独拦截（其中 `adenocarcinoma`、`squamous cell carcinoma` 仍因含 `carcinoma` 命中，`tumor microenvironment` 仍因含 `tumor` 命中，`肿瘤微环境`/`癌细胞`/`癌症` 仍因含 `肿瘤`/`癌` 命中）；`领域下拉含"免疫"` 与拦截 `免疫浸润` 不冲突——"免疫"作为研究领域合规，"免疫浸润"作为肿瘤机制词拦截。
* **模块 B（数据来源、动态多分组与组内样本编号绑定）**：
* **基础数据源信息**：数据库来源（GEO / ArrayExpress / 自有数据）、训练集编号（`train_gse`）、独立外部验证集编号（`val_gse`）、平台编号（`gpl`）、总样本数、非肿瘤非免疫组织来源，以及选填协变量（批次 `batch_col`、年龄、性别）。
* **动态多分组管理（支持 $N \ge 2$ 组及多阶段疾病演进）**：支持三种分组模式（`二分类对比` / `多组无序对比` / `有序病情阶段演进`），动态点击 `[+ 新增分组]` 自由扩展分组数量，指定基准对照组（Reference）与阶段顺序（`stage_order`）。
* **组内样本编号（GSM / Sample ID）录入与防重校验**：每个分组卡片内置样本编号多行文本域（支持逗号、空格、换行批量粘贴），前端实时统计各组样本数并执行跨组重复分配拦截。支持一键导入两列 `Sample_ID, Group_Name` 映射表。
* **显式差异对比对（Contrasts）配置**：当分组数 $\ge 3$ 时，支持显式勾选差异分析对比组合并指定主对比对（Primary Contrast）。
* **分片上传器**：4MB 分片断点续传（已实现：uploadId 由「项目 + 归属线 + 文件名 + 大小 + 修改时间」经 shared/upload_session.mjs 确定性派生，刷新/换浏览器/换设备都能凭 GET /api/upload/status 从 nextIndex 续传；服务端 24 小时未动的会话由 GC 自动清理，BIO_UPLOAD_TTL_HOURS 可覆盖）并自动校验 Bulk 与单细胞/空间数据格式。
* **数据格式白名单与体积上限（单一事实源）**：14 类扩展名（`.h5ad` / `.h5` / `.loom` / `.mtx` / `.tar` / `.gz` / `.zip` / `.txt` / `.tsv` / `.csv` / `.soft` / `.xlsx` / `.rds` / `.rdata`）与单文件 `5GiB` 上限统一由 `shared/data_formats.mjs` 的 `DATA_EXT` / `MAX_DATA_BYTES` 维护，工作台 8787 与客户提交台 8080 共用同一份；提交台仍可用 `PORTAL_MAX_DATA_BYTES` 覆盖上限。改白名单只改该文件，再同步 `portal/index.html` 的字面量、`accept` 属性与提示文案（两侧一致性由 `BioanalysDesktop/tests/data_format_parity.test.js` 把守）。


* **模块 C（级联流水线编排与全节点功能说明展示）**：
* **第一级（单选物理锁）**：必选归属分析线（`line1_bulk` / `line2_scrna` / `line3_spatial`），选定后锁定对应物理目录并屏蔽其余两条线的所有功能。
* **第二级（带功能详解的模块勾选与排序）**：前置 QC/标准化模块固定锁死在前序位置；下游模块支持勾选与排序。每个分析节点卡片在界面上直观展示 **4 项标准化说明**：① 功能简介（该步骤解决的生物学问题）、② 核心工具/算法（R/Python 实际工具栈）、③ 输入/输出产物（图表与 .tsv 名称）、④ 条件必填项与算力提示。若勾选“虚拟敲除”，强制弹出 `target_ko_gene` 必填框。
* **第三级（算法与参数设置）**：支持展开配置关键阈值，留空则采用 K40 12G 运存安全默认值。


* **模块 D（项目权限、算力保护策略确认与预期交付物说明）**：
* **项目成员与权限设置（ACL）**：区分项目负责人（`owner`，完整执行与重跑权限）与只读协作者（`collaborator`，仅开放结果预览与下载）。
* **算力削峰与断点恢复策略展示**：只读说明卡片，确认 nice/ionice 降权执行（**默认不静态绑核**——2026-10-20 契约变更，实测 EAS 动态调度更快，见 §六.3）、3 线程封顶、`7.5GB` 内存软熔断及基于 `exit 0` 检查点的断链自动续跑。
* **预期输出结果配置（Expected Deliverables）**：带规格说明的勾选卡片，包括 Web 预览图集 (`300 DPI .png`)、全量统计结果表 (`.tsv`)、发表级矢量图副本 (`.pdf/.svg`，选填)、中间态检查点 (`.rds/.h5ad`)、结构化审计台账 (`system_logs/*.json`，区分 DEG vs DR Genes)。

### 2. 客户分析输入端（Customer Input Console）

供已建项目在日常运行中快速核对 GSE/GPL 分组信息、微调单步参数、触发断点续跑及查看当前流水线实时进度。

* **任务提交三道闸**：① 路径归属预校验——输入/输出必须落在 §二 的合法根内且归属当前项目，越界直接 `400`；② 命令审计——脚本中出现其他分析线字符串一律拒绝（`server/audit.js`）；③ 桥接四项断言——脚本涉及 R/Python 切换时，提交层调用 `ops/verify_bridge_checkpoint.py`，断言不过即 `400` 并回传断言明细。
* **断点续跑契约**：以 `exit 0` + 产物存在性为检查点；台账 JSON 落 `system_logs/`，`status` 取 `running` / `completed` / `failed`。

### 3. 服务端运维与审计控制台（Server Admin & Self-Check Console）

* **五维环境自检界面（Pre-flight Dashboard）**：
1. **路径与 FUSE 红线检查灯**：只读执行 `df -T /mnt/ssd/bio_data`，确认为 `ext4`/`f2fs`，若出现 `fuse` 立即阻断。
2. **F2FS 存储水位门禁灯**：可用空间低于 `20%` 时触发告警并阻断新任务提交，防前台阻塞式 GC。
3. **SoC 算力、温度与 7.5G 内存监控灯**：实时展示 CPU 负载率（默认不绑核，EAS 动态调度，2026-10-20 契约变更）、传感器温度及容器 `7.5GB` 内存配额水位。
4. **跨线隔离与 R/Python 桥接自检灯**：静态扫描脚本无跨线路径字符串；展示 R/Python 转换四项断言校验结果。
5. **ADB/SSH 守护链路存活灯**：展示本地 `00_link_check.ps1` 心跳状态与 `tmux` 守护会话 PID。

* **自检实现口径（`GET /api/selfcheck`，纯函数集中在 `BioanalysDesktop/server/selfcheck.js`）**：每维四档 `pass` / `warn` / `fail` / `unknown`，汇总 `all_pass` 仅在既无 `warn` 也无 `fail` 时为真；远端输出缺 `END` 结束标记时判 `unknown`，不冒充通过。
  * 第 2 维：可用 ≥ `20%` 为 pass，否则 fail，阈值与 `ops/check_storage_and_isolation.sh` 的 `MIN_FREE_PERCENT=20` 同源。
  * 第 3 维：读 `/proc/loadavg`、`nproc`、`/sys/class/thermal`、cgroup v2 `memory.max` / `memory.current`；温度 ≥ `85°C` warn / ≥ `95°C` fail；内存 ≥ `90%` warn / ≥ `100%` fail；负载 ÷ 核数 ≥ `1.5` warn；配额按 `7.5GB` 展示。
  * 第 4 维：三条线逐线跑 `check_storage_and_isolation.sh`（任一线非 0 即 fail，并点明是哪条线），再查 `ops/verify_bridge_checkpoint.py` 是否在位（缺则 warn）。

### 2. 存储水位、FUSE 红线与跨线隔离门禁（`ops/check_storage_and_isolation.sh`）

```bash
#!/bin/bash
# 用法: bash /mnt/ssd/bio_data/ops/check_storage_and_isolation.sh <line_id> <script_path>
set -e
LINE_ID="$1"
SCRIPT_PATH="$2"
TARGET_DIR="/mnt/ssd/bio_data"
MIN_FREE_PERCENT=20

# 1. 校验分析线合法性
if [[ "$LINE_ID" != "line1_bulk" && "$LINE_ID" != "line2_scrna" && "$LINE_ID" != "line3_spatial" ]]; then
    echo "[FATAL] 非法的流水线标识: $LINE_ID，严禁越界执行！"
    exit 1
fi

# 2. 路径红线只读检查：拒绝 FUSE 模拟层 (/sdcard 等)
FS_TYPE=$(df -T "$TARGET_DIR" | awk 'NR==2 {print $2}')
if [[ "$FS_TYPE" == *"fuse"* || "$FS_TYPE" == *"sdcardfs"* ]]; then
    echo "[FATAL] 数据目录 ($TARGET_DIR) 文件系统为 $FS_TYPE (FUSE层)，违反原生分区红线，阻断任务！"
    exit 1
fi

# 3. F2FS/ext4 存储水位只读检查 (<20% 阻断防阻塞式 GC)
USED_PERCENT=$(df -P "$TARGET_DIR" | awk 'NR==2 {print $5}' | tr -d '%')
FREE_PERCENT=$((100 - USED_PERCENT))
if [ "$FREE_PERCENT" -lt "$MIN_FREE_PERCENT" ]; then
    echo "[ERROR] 原生存储剩余空间低于安全阈值：剩余 ${FREE_PERCENT}%, 要求 >= ${MIN_FREE_PERCENT}%."
    echo "[ABORT] 触发 F2FS 前台 GC 保护门禁，阻断新任务提交。"
    exit 1
fi

# 4. 跨线路径静态扫描 (严禁当前脚本引用其他两条线的目录)
for OTHER_LINE in "line1_bulk" "line2_scrna" "line3_spatial"; do
    if [ "$OTHER_LINE" != "$LINE_ID" ]; then
        if grep -q "$OTHER_LINE" "$SCRIPT_PATH"; then
            echo "[FATAL] 检测到跨线数据引用违规！脚本 $SCRIPT_PATH (归属 $LINE_ID) 试图访问 $OTHER_LINE！"
            exit 1
        fi
    fi
done

echo "[OK] 门禁校验全部通过：文件系统=$FS_TYPE | 剩余空间=${FREE_PERCENT}% | 物理隔离线=$LINE_ID"
exit 0

```

> **同口径要求（2026-10-21）**：工作台 8787 五维自检的第 2/3/4 维与本脚本共用阈值——存储水位 `20%`、温度 `85°C` 告警 / `95°C` 阻断、内存配额 `7.5GB`、三条线逐线执行本脚本。改阈值必须同时改 `BioanalysDesktop/server/selfcheck.js` 与本脚本，避免「界面绿、脚本红」。

### 3. 统一降权执行与自动化台账包装器（`ops/run_throttled_task.sh`）

> **2026-10-20 契约变更（用户拍板）**：默认**不静态绑核**。实测依据
> （`docs/k40_cpu_affinity.md` §七，交替验证 3 轮每轮全胜）：「不绑核 + 3 线程」比
> 原契约「taskset -c 4,5,6 + 3 线程」快 ~30%（Python matmul）/ 6-11%（R）——
> EAS 动态调度可上 Prime 3.19GHz，静态绑 2.42GHz 大核反而封顶单线程上限；
> OpenBLAS NO_AFFINITY 特性也与动态调度配合更好。保留 `BIO_PIN_CPUS=4,5,6`
> 开关可恢复绑核；绑核失败（Android 动态核隔离可致 EINVAL，实测发生过）自动
> 降级为不绑核，任务不因绑核失败而夭折。

```bash
#!/bin/bash
# 用法: nohup bash /mnt/ssd/bio_data/ops/run_throttled_task.sh <task_id> <line_id> <step_name> <R|Python> <script_path> &
set -e
TASK_ID="$1"
LINE_ID="$2"
STEP_NAME="$3"
LANG="$4"
SCRIPT_PATH="$5"

bash /mnt/ssd/bio_data/ops/check_storage_and_isolation.sh "$LINE_ID" "$SCRIPT_PATH"

START_TIME=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
LOG_FILE="/mnt/ssd/bio_data/system_logs/${TASK_ID}.log"
LEDGER_JSON="/mnt/ssd/bio_data/system_logs/${TASK_ID}_ledger.json"

EXEC_CMD=$([ "$LANG" == "Python" ] && echo "python3" || echo "Rscript")

set +e
# 核心削峰动作（契约 2026-10-20）：默认不绑核，仅 nice/ionice 降权；
# EAS 动态调度可用 Prime 核；BIO_PIN_CPUS=4,5,6 可恢复静态绑核（失败自动降级）
BIO_PIN_CPUS="${BIO_PIN_CPUS:-}"
AFFINITY_PIN=""
AFFINITY_DESC="无绑核（EAS 动态调度）"
if [ -n "$BIO_PIN_CPUS" ]; then
    if taskset -c "$BIO_PIN_CPUS" true 2>/dev/null; then
        AFFINITY_PIN="taskset -c $BIO_PIN_CPUS"
        AFFINITY_DESC="taskset -c $BIO_PIN_CPUS"
    else
        echo "[wrapper] BIO_PIN_CPUS=$BIO_PIN_CPUS 不可用，降级为不绑核"
        AFFINITY_DESC="BIO_PIN_CPUS 不可用降级"
    fi
fi
$AFFINITY_PIN nice -n 10 ionice -c 2 -n 4 $EXEC_CMD "$SCRIPT_PATH" > "$LOG_FILE" 2>&1
EXIT_CODE=$?
set -e

END_TIME=$(date -u +"%Y-%m-%dT%H:%M:%SZ")
STATUS=$([ $EXIT_CODE -eq 0 ] && echo "completed" || echo "failed")

cat <<EOF > "$LEDGER_JSON"
{
  "task_id": "$TASK_ID",
  "line_id": "$LINE_ID",
  "step_name": "$STEP_NAME",
  "status": "$STATUS",
  "start_time": "$START_TIME",
  "end_time": "$END_TIME",
  "environment": {
    "language": "$LANG",
    "wrapper": "$AFFINITY_DESC nice -n 10 ionice -c 2 -n 4",
    "memory_limit_gb": 7.5
  },
  "checkpoint_status": "$([ $EXIT_CODE -eq 0 ] && echo "passed" || echo "halted")",
  "error_log": "$([ $EXIT_CODE -eq 0 ] && echo "null" || echo "$LOG_FILE")"
}
EOF
exit $EXIT_CODE

```
