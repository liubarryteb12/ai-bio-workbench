## 一、 架构拓扑与三大铁律

### 1. “云-端”解耦架构拓扑

* **本地交互与编排层（零算力消耗）**：本地终端仅运行 Web 浏览器及两个彻底解耦的 Node.js 服务（`8787` 工作台服务端 + `8080` 客户门户提交台）或轻量级 IDE（VS Code Remote-SSH）。本地不参与任何生信计算，仅通过 `ssh`/`scp`/`adb` 执行编排、审计与交付回搬。


* **网络传输与自愈层**：SSH 隧道加密传输控制流与代码流；HTTP/S（配合外网穿透与可选 Token 鉴权）支持远程建项、大文件分片断点上传与结果预览；本地通过 `ops/00_link_check.ps1` 实现断链自动重连（`adb forward` 重建 + `monkey` 自动拉起 Termux 服务）。


* **远程计算与存储层（红米 K40 核心底座 + 弹性节点池）**：
* **物理硬件**：主节点为红米 K40（骁龙 870 八核处理器 + **12GB LPDDR5 运存** + **原生 UFS 3.1 高速闪存**，配合外置风冷与充电限流/旁路供电）；架构层面在 `server/task.js` 预留 SSH 计算节点池抽象，当主节点触发高温熔断（$\ge 95^\circ\text{C}$）或硬件离线时，支持平滑路由至备用同构节点。


* **系统与容器层**：Android (Termux 底座，**无 Root 约束**，`ssh k40:8022`) + Ubuntu 24.04 (ARM64 proot 容器，`ssh k40-ubuntu:10022`)，通过 Conda/R 独立环境实现三条分析线的依赖隔离。


* **长任务守护层**：所有计算任务强制通过 `nohup` / `tmux` 后台守护运行，基于每步退出码（`exit 0`）与产物校验实现断点续跑。





### 2. 三大不可逾越的执行铁律

1. **非肿瘤、非免疫浸润专精原则**：
* 全流程专精非肿瘤领域（心脑血管、神经退行、代谢、纤维化、发育等），严禁主动加入临床生存预后、肿瘤免疫浸润、药物敏感性预测等未要求内容。


* 建项时前后端双保险拦截：权威规格正本为 **§三.1 模块 A 的 20 条黑名单**（2026-10-21 二次裁定：以 aims 为准，吸纳实现侧 27 条中可用的 12 条，剔除 8 条冗余项），单一事实源为 `BioanalysDesktop/server/tumor_blacklist.js`；提交台 `portal/index.html` 由 `portal/serve.mjs` 动态注入或由 `BioanalysDesktop/tests/tumor_blacklist_parity.test.js` 强一致把守。




2. **三条平行分析线物理与逻辑硬隔离原则**：
* **线 1**：GEO Bulk 线（`line1_bulk`）


* **线 2**：单细胞转录组 + 虚拟敲除线（`line2_scrna`）


* **线 3**：单细胞空间转录组 + 虚拟敲除线（`line3_spatial`）


* **隔离红线**：三条线不互相取参考、不合并数据集、不跨线验证。**虚拟敲除绝不是第四条独立线**，而是线 2（第 10 步）和线 3（第 9 步）各自的末端模块。




3. **R / Python 线内最优分工与阶段感知单向桥接原则**：
* 仅允许同一条线内部按工具优势混用 R 与 Python，严禁跨线混用。固定主语言、包版本与全局随机种子（`seed = 20261013`），严格控制语言切换次数（线 1 切换 1 次；线 2 切换 2 次；线 3 全程 Python 0 次切换）。


* 每次跨语言转换必须通过**桥接四项断言检查点**（① 基因名 Symbol 完整性、② 矩阵行列方向与稀疏性、③ 细胞 Barcode 顺序、④ 降维/空间坐标保留），由 `ops/verify_bridge_checkpoint.py` 自动执行。


* **阶段感知（Stage-Aware）规则**：默认执行 `--stage post-dimred`（无 `X_pca`/`X_umap`/`spatial` 即 `FAIL` 阻断）；若确系降维前的早期标准化矩阵跨语言交互，母版须显式传入 `--stage pre-dimred`（降级为 `[BRIDGE WARN]` 放行并记入台账），严禁无声放宽引擎校验标准。


* **DEG 与 DR Genes 严禁混写**：差异表达基因（DEG，转录本丰度变化）与虚拟敲除差异调控基因（DR Genes，调控网络拓扑微扰）在命名、表格、图件角标与解读文本中必须物理隔离。

### 合法根与归属口径（单一事实源：`BioanalysDesktop/server/ledger.js` 的 `analyzePath` / `inspectTaskPath`）

* **四种合法输入/输出形态**：① `/mnt/ssd/bio_data/projects/<当前项目>/...` 下任意子路径；② `/mnt/ssd/bio_data/public_references/...`（**强只读**，仅可作输入，严禁作为输出目录）；③ 迁移前历史三线形态 `/mnt/ssd/bio_data/<line>/...`（仅台账历史审计兼容，任务提交侧直接拦截）；④ **裸相对文件名**（任务脚本先 `cd` 到 `<项目>/<线>/processed/`，由 shell 解析）。


* **独占与禁区**：`system_logs/` 由台账通道独占写入，禁止作为任务输入或输出。


* **防歧义拦截**：相对路径只接受**裸文件名**与 **`projects/<项目>/...`** 两种形态；`processed/x.tsv` 这类「子目录 + 文件名」在提交层直接回 `400`（报「相对路径缺少合法根」），彻底消除 `cwd` 歧义。


* **安全边界**：项目段比对**大小写敏感**；任何含 `..` 的路径在归一化之前一律拒绝。提交层（`POST /api/tasks/submit`）、台账审计（`classifyPath` / `auditLedgerEntry`）、文件访问守卫三处共用同一套合法根，严禁各自维护副本。

## 三、 工作台前端与服务端四大视图界面设计

### 1. 独立页面：新建项目向导页（Project Onboarding Portal - 8080）

与 8787 工作台彻底解耦，支持可选 Token 鉴权外网访问，所有表单操作与后端建项契约 `project_manifest.json` 1:1 对齐：

* **模块 A（项目基本信息与非肿瘤合规拦截）**：
* 填写项目名称、项目描述、物种（`Homo sapiens` / `Mus musculus` / `Rattus norvegicus`）、非肿瘤研究领域下拉框、具体疾病名称（前端即时红字拦截 + 后端建项前权威复核双保险）。


* **黑名单确认清单（20 条规格正本，`BioanalysDesktop/server/tumor_blacklist.js` 逐条实现）**：


* **英文 16 条**：`cancer`、`tumor`、`tumour`（英式拼写）、`carcinoma`、`glioma`、`sarcoma`、`lymphoma`、`leukemia`、`leukaemia`、`melanoma`、`immune infiltration`（正则 `immune\s*infiltration`）、`immune checkpoint`（正则 `immune\s*checkpoint`）、`PD-L1`（正则 `(?<![A-Za-z0-9])PD-?L1(?![0-9])`）、`PD-1`（正则 `(?<![A-Za-z0-9])PD-?1(?![0-9])`）、`CTLA-4`（正则 `CTLA-?4`）、`oncogene`；


* **中文 4 条**：`肿瘤`、`癌`、`免疫浸润`、`免疫检查点`；


* **匹配规则**：英文全部 `i` 大小写不敏感，中英文按子串匹配（如“癌”命中“癌变/致癌物”、“非肿瘤”命中“肿瘤”，属预期拦截）。**唯一例外**是 `PD-L1` / `PD-1` 两条必须带左右边界，否则 `GPD1`、`SLC40A1` 这类基因符号会被误伤（2026-10-21 实测）。


* **沿革（2026-10-21 二次裁定）**：本清单最初为 8 条（`cancer`/`tumor`/`carcinoma`/`glioma`/`immune infiltration`/`肿瘤`/`癌`/`免疫浸润`）；实现侧历史自行扩充到 27 条，同日先被收敛回 8 条，随后用户裁定「以 aims 为准，吸纳 27 条中可用的并对齐」。**可用判据三条**：① 明确属肿瘤或免疫浸润语义；② 不被既有父词覆盖（冗余项不入清单）；③ 误伤风险可接受。据此吸纳 12 条（见上），剔除 8 条冗余项：`adenocarcinoma`、`squamous cell carcinoma`（均含 `carcinoma`）、`tumor microenvironment`、`tumour microenvironment`、`tumor suppressor`（均含 `tumor`/`tumour`）、`癌症`（含 `癌`）、`肿瘤微环境`（含 `肿瘤`）、`癌细胞`（含 `癌`）。最终 8 + 12 = 20 条。


* **治理纪律**：严禁开发人员未经规格裁定私自扩充拦截词；`portal/serve.mjs` 在响应 `portal/index.html` 时支持编译期/运行期注入共享契约，且两侧一致性由 `tumor_blacklist_parity.test.js` 强制把守。






* **模块 B（数据来源、动态多分组、样本绑定与硬配额分片上传）**：
* **基础数据源与多分组管理**：支持 GEO / ArrayExpress / 自有数据；支持 `二分类对比` / `多组无序对比` / `有序病情阶段演进`（动态扩展 $N \ge 2$ 组，指定 Reference 与 `stage_order`）；组内 GSM/Sample ID 批量粘贴实时统计并执行**跨组重复分配拦截**；分组 $\ge 3$ 时支持显式勾选对比组合并指定 Primary Contrast。


* **数据格式白名单与体积上限（单一事实源 `shared/data_formats.mjs`）**：14 类扩展名（`.h5ad` / `.h5` / `.loom` / `.mtx` / `.tar` / `.gz` / `.zip` / `.txt` / `.tsv` / `.csv` / `.soft` / `.xlsx` / `.rds` / `.rdata`）与单文件 `5GiB` 上限统一由 `DATA_EXT` / `MAX_DATA_BYTES` 维护，8787 与 8080 共用，由 `data_format_parity.test.js` 把守。


* **分片断点续传与配额治理（`shared/upload_session.mjs` + `server/upload.js`）**：
* **确定性会话**：4MB 分片，基于「项目 + 归属线 + 文件名 + 大小 + 修改时间」确定性派生 `uploadId`，支持跨刷新/跨设备凭 `GET /api/upload/status` 从 `nextIndex` 续传。


* **两段式 GC 与预留硬闸门**：24 小时未动会话由 TTL GC 自动清理（`BIO_UPLOAD_TTL_HOURS` 可覆盖）；`.uploads` 总占用受 `BIO_UPLOAD_QUOTA_BYTES`（默认 `20GiB`）管控。**硬化规则**：`POST /api/upload/init` 阶段将声明的 `fileSize` 写入会话元数据 `reservedBytes` 进行原子预留，超配额时按 mtime 由旧到新淘汰非活跃会话（10 分钟内写过的活跃会话受保护），仍超限则回 `507 Insufficient Storage`；`POST /api/upload/chunk` 写盘前校验 `receivedBytes + chunk.length <= reservedBytes`，超限立即回 `413` 阻断，防止并发写穿存储水位。


* **统一错误契约**：四个上传端点（`init` / `chunk` / `status` / `complete`）的 4xx/5xx 响应体统一为 `{ok: false, error}`。






* **模块 C（级联流水线编排与全节点功能说明展示）**：
* **第一级（单选物理锁）**：必选一条归属分析线，锁定对应物理目录并屏蔽其余两条线。


* **第二级（节点说明与排序）**：前置 QC 固定锁死，下游支持勾选排序；卡片强制展示 **4 项标准化说明**（① 功能简介、② 核心工具/算法、③ 输入/输出产物、④ 条件必填项与算力提示）；勾选“虚拟敲除”强制弹出 `target_ko_gene` 必填框。


* **第三级（参数设置）**：支持展开配置关键阈值，留空则采用 K40 安全默认值。




* **模块 D（项目权限、算力保护策略确认与预期交付物说明）**：
* 区分 `owner` 与 `collaborator` 权限；展示 EAS 动态调度（默认不静态绑核）、3 线程封顶、`7.5GB` 内存软熔断及 `exit 0` 断点续跑策略；勾选预期交付格式。





### 2. 客户分析输入端（Customer Input Console）

* **任务提交三道闸（`POST /api/tasks/submit`）**：
1. **路径归属预校验**：调用 `ledger.js` 的 `inspectTaskPath`，越界或非裸相对路径直接 `400`。


2. **命令跨线审计**：`server/audit.js` 静态扫描脚本，出现其他分析线路径或标识一律拒绝。


3. **去注释双语识别与双层桥接守卫**：
* `server/task.js` 的 `inspectBridgeNeed` 必须先通过 `stripShellAndCodeComments` **剥离全部纯注释行与行尾注释**（仅保留 `#!` shebang），再判定是否同时含 R 与 Python 调用，严禁因注释文字误判 bilingual。


* **双保险机制**：提交层自动调用 `ops/verify_bridge_checkpoint.py` 预检；bilingual 母版内部在首次 `Rscript` 前必须自调 `src/bridge_guard.sh`（由 `tests/bridge_guard_invariant.test.js` 钉死为可执行不变量）。守卫的引擎解析顺序是**本机优先、ssh 兜底**（母版就跑在计算容器里，从容器里 ssh 回宿主是反模式，会让断言恒 `SKIP`）；本机模式（`MODE=local`）下引擎非 0 退出即判 `[BRIDGE FAIL]` 并中止母版，只有 ssh 不可达（退出码 255 / 超时）才降级 `SKIP` 放行。







### 3. 服务端运维与审计控制台（Server Admin & Self-Check Console - 8787）

* **五维环境自检界面（`GET /api/selfcheck` $\rightarrow$ `server/selfcheck.js`）**：每维输出 `pass` / `warn` / `fail` / `unknown` 四档，远端输出缺 `END` 标记一律判 `unknown`；仅当无 `warn` 且无 `fail`/`unknown` 时 `all_pass = true`：


1. **路径与 FUSE 红线检查灯**：`df -T /mnt/ssd/bio_data` 确认为 `ext4`/`f2fs`，遇 `fuse`/`sdcardfs` 立即 `fail` 阻断。


2. **F2FS 存储水位与上传暂存监控灯**：可用空间 `< 20%` 立即 `fail` 并阻断新任务与新上传；实时展示 `.uploads` 存活会话数与预留配额占用率。


3. **SoC 算力、温度与 7.5G 内存监控灯**：展示 CPU 负载率（负载 $\div$ 核数 $\ge 1.5$ 为 `warn`）、传感器温度（$\ge 85^\circ\text{C}$ `warn` / $\ge 95^\circ\text{C}$ `fail`）、cgroup v2 内存水位（按 `7.5GB` 配额计，$\ge 90\%$ `warn` / $\ge 100\%$ `fail`）。


4. **跨线隔离、桥接引擎与远端版本一致性灯**：逐线跑 `check_storage_and_isolation.sh`；检查 `verify_bridge_checkpoint.py` 在位状态；**比对本地与远端 `bridge_guard.sh` 及核心母版的 SHA256 校验和，不一致即判 `warn`/`fail` 防版本漂移**。三件事共用一盏灯：隔离门禁与 SHA256 比对各自出状态，取最坏（`fail` > `warn` > `unknown` > `pass`）合并上报，`detail` 必须点名到具体坏在隔离还是坏在版本漂移（`selfcheck.js` 的 `mergeIsolationChecks`）。第 1~4 维的远端读数一律走严格执行（`proc.js` 的 `runSshStrict`）：ssh 退出码非 0 或输出为空即抛错落 `unknown`，**严禁把空输出当成「读到了空值」判 `pass`**（假绿灯比红灯危险）。**注意远端有两个落点**：自检第 4 维比的是「仓库 vs 远端 `src/` 镜像」（审计副本），而任务引擎通过 PATH 执行的是 `bin/<线>/<步骤名>`（由 `ops/06_deploy_scripts.ps1` 部署）；两者长期可能不一致，故 `ops/sync_and_verify_remote.ps1` 第 6 步单独核对「仓库 vs `bin/` 落点」，漂移写进 manifest 的 `deploy` 字段与台账「部署」列，`-FailOnDrift` 时漂移即 exit 1（见 SPEC_DECISIONS D-17）。


5. **ADB/SSH 守护链路存活灯**：展示本地 `00_link_check.ps1` 心跳状态与远端 `tmux` 守护会话 PID。

## 六、 红米 K40 (8核 12G 运存) 算力优化、防崩与同步套件（无 Root 纯净版）

### 1. 容器全局线程封顶配置（`/etc/profile.d/bio_limits.sh`）

锁死 `OMP_NUM_THREADS=3`、`OPENBLAS_NUM_THREADS=3`、`MKL_NUM_THREADS=3`、`VECLIB_MAXIMUM_THREADS=3`、`NUMEXPR_NUM_THREADS=3`、`R_DATATABLE_NUM_PROCS_PERCENT=50`、`MPLBACKEND=Agg`。

### 2. 存储水位、FUSE 红线与跨线隔离门禁（`ops/check_storage_and_isolation.sh`）

执行四项硬检查：① 校验 `$LINE_ID` 合法性；② `df -T` 拒绝 `fuse`/`sdcardfs`；③ `df -P` 检查可用空间 $\ge 20\%$（防 F2FS 前台阻塞式 GC）；④ 静态扫描目标脚本（剥离纯注释行后）不得引用其他两条线的目录字符串。阈值与 `server/selfcheck.js` 严格同源。

### 3. 统一降权执行、热节流保护与自动化台账包装器（`ops/run_throttled_task.sh`）

* **EAS 动态调度契约**：默认**不静态绑核**（实测 EAS 动态调度可调用 3.19GHz Prime 核，较静态绑大核提速 6%~30%，且规避 Android 动态核隔离导致的 `taskset EINVAL` 崩溃），仅通过 `nice -n 10 ionice -c 2 -n 4` 降权运行；保留 `BIO_PIN_CPUS` 环境变量作为可选降级开关。


* **高温自适应冷却保护**：任务启动前若检测到 `/sys/class/thermal` 温度 $\ge 90^\circ\text{C}$，包装器自动进入 `sleep 30` 冷却等待循环并写入日志，待温度回落至 $< 78^\circ\text{C}$ 后再拉起计算进程，防止长任务中途因热保护被系统强杀。
* **Python / R 7.5GB 内存防崩头**：Python 脚本顶部强制调用 `resource.setrlimit(resource.RLIMIT_AS, (7.5*1024**3, 7.5*1024**3))`；R 脚本顶部强制设置 `data.table::setDTthreads(3)`、`future::plan("multisession", workers = 2)` 与 `options(future.globals.maxSize = 6.0 * 1024^3)`。



### 4. 本地与远端代码原子同步与校验工具（`ops/sync_and_verify_remote.ps1`）

任何对 `ops/`、`src/bridge_guard.sh` 及 `src/<line>/scripts/` 母版的修改，严禁手工零散 `scp`；必须执行 `ops/sync_and_verify_remote.ps1`，自动完成：① LF 换行符归一化校验（配合 `.gitattributes`）；② 推送至远端 `/mnt/ssd/bio_data/bin/` 或 `ops/`；③ 比对本地 `Get-FileHash -Algorithm SHA256` 与远端 `sha256sum`，完全一致后将同步凭证追加写入 `con_hf/ops_ledger.md` 与远端 `system_logs/sync_manifest.json`。

## 七、 顾问协作与交互标准协议（永久执行）

### 2. 四项铁腕工程治理纪律

1. **证据优先与零推测纪律（Evidence-First）**：
* 任何报告、台账与状态汇报中，完成度、测试通过数、文件校验和必须来自 `git log`、`npm test`、`sha256sum` 的**实测输出**。未取得实测证据的条目一律显式标注「待补充」或 `unknown`，严禁主观推测或捏造绿灯。




2. **文件域写隔离与契约冲突升级纪律（Write-Scope Isolation）**：
* 并行开发时，每个切片 Agent 只能修改声明的 `write_scopes` 文件域。凡涉及 `shared/*.mjs`、`server/ledger.js`、`aims/aims.txt` 等全局契约文件的修改，统一由 Lead Agent 集中裁决合入，防止并发覆写与整表 `deepEqual` 断言雪崩。




3. **三位一体防漂移纪律（Spec-Code-Test Parity）**：
* **改条款必改落点与断言**：修改 `aims.txt` 任何规则，必须在同一 git commit 中同步更新对应实现代码与 `BioanalysDesktop/tests/` 下的防漂移断言。


* **断言红灯处置铁律**：当 `npm test` 断言变红时，**第一优先级怀疑实现代码或远端环境发生漂移**，严禁为了凑绿灯而随意注释、删减或放宽测试断言。




4. **提交与发布前置门禁（Pre-commit & Release Gate）**：
* 本地提交前必须 100% 通过三连检：`npm test`（全量断言全绿） $\rightarrow$ `npx tsc --noEmit`（零类型错误） $\rightarrow$ `npm run build`（前端构建通过）。

### 2. 生产级风险预案与自动降级矩阵

| 风险类别 | 监控探针与触发阈值 | 自动化保护动作（System Action） | 人工介入与台账回写要求 |
| --- | --- | --- | --- |
| **SoC 高温热节流 / 熔断** | `/sys/class/thermal` $\ge 85^\circ\text{C}$ (`warn`) / $\ge 95^\circ\text{C}$ (`fail`)

 | 8787 自检灯变红并阻断新任务提交；运行中任务的 `run_throttled_task.sh` 在步间触发冷却休眠，待 $< 78^\circ\text{C}$ 自动续跑。

 | 检查外置散热器与旁路供电状态；异常高温记入 `ops_ledger.md`。

 |
| **7.5GB 内存配额逼近 / OOM** | cgroup v2 `memory.current` $\ge 90\%$ (`warn`) 或进程因 `RLIMIT_AS` 退出

 | 立即停止后续步骤，台账记 `status: failed, checkpoint_status: halted`；保留前序已 `exit 0` 的 `.rds`/`.h5ad` 检查点。

 | 按 §四 规范开启 Pseudo-bulk 或下采样参数（如 `nc_nCells=500`），记入 `pitfalls_ledger.md` 后从断点续跑。

 |
| **F2FS 存储水位低于红线** | `df -P /mnt/ssd/bio_data` 剩余空间 $< 20\%$<br> | `check_storage_and_isolation.sh` 与交付第 1 道闸同时阻断新任务与新上传；自动触发 `gcStaleUploads` 清理非活跃分片。

 | 将已签收项目的中间 `.h5ad`/`.rds` 冷备回搬至本地 PC 并清理远端，在 `ops_ledger.md` 记录清理释放容量。

 |
| **远端与本地版本漂移** | 五维自检第 4 维检测到核心脚本 SHA256 不一致

 | 自检汇总 `all_pass` 置为 `false`，在任务提交面板弹出版本不一致告警。
