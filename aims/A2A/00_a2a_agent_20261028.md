## 第一部分：对双 Agent 跨端协作痛点的深度复盘与架构诊断

### 1.1 为什么必须采用“传算解耦 + A2A 本地自治 + 微内核插座 + 1+N×3 文档体系”，而非传统跨网逐命令直控？

在“电脑 Codex / BioanalysDesktop (`18787`) + 手机 Termux Pi Agent”双端协同场景中，传统做法是让电脑端通过 SSH/MCP 隔着网络逐条下发命令操控手机。实测表明，一旦网络闪断或任务耗时较长，传统耦合模式就会引发灾难性的**“断链整步重跑”**，并在工程落地中暴露出 **9 大结构性缺口（G1 ~ G9）**。

通过确立 **“电脑负责写代码与确定性传文件 ──► 手机 Pi Agent 作为本地严格执行者（Strict Runner）自治跑完构建内容 ──► 18787 工作台实时观测与管控模型”** 的全景架构，可一次性根治全部 9 大缺口：

| 缺口编号 | 现存具体工程问题（实测暴露的痛点与风险） | 传统耦合/粗放架构的病灶根源 | 微内核插座 + A2A v1.0 + 1+N×3 体系的根治方案 |
| :--- | :--- | :--- | :--- |
| **G1：网卡暴露与无鉴权裸奔风险** | `@bacnh85/pi-a2a` 若直接将 `server.host` 从 `127.0.0.1` 改为 `0.0.0.0` 而未配置 `peerTokens`，局域网或虚拟网内任意节点均可向 `:9910` 发送 `SendMessage` 驱动 Pi 执行任意 Shell。 | 网卡绑定配置与鉴权字典缺乏编译期/启动期联动锁，安全策略沦为人工口头约定。 | 立项 **D-03** 与 `security-audit-engine`：强制实施“零信任绑定守卫”，启动脚本与 `ModManifest` 双重校验 `host === "0.0.0.0"` 时 `peerTokens` 必须非空且长度 $\ge 32$ 字符，否则直接拒绝拉起并退出码 `2`。 |

### 1.1.1 通信面澄清：Codex 直接派发，18787 只负责观测

Codex 与 Pi 的主执行通道是 A2A v1.0 的 `SendMessage`、`GetTask` 与 `CancelTask`。Codex 直接向 Pi 的 `:9910` 派发结构化任务单，Pi 执行后回传结构化 Artifact。`18787` 是观测、模型切换和人工派发面，不参与 Codex 到 Pi 的模型调用链，也不是任务执行的必经中间层。

正式任务统一采用两阶段验收：

1. Codex 派单，任务单写明目标、工作目录、输入、输出、验收命令、超时和工具调用上限。
2. Pi 执行任务并完成初步验收，回传 `preliminary_acceptance` 和结构化 Artifact。
3. Codex 读取初步验收报告，独立核对哈希、退出码、产物、测试结果和修改范围，完成 `final_acceptance`。
4. 只有 Codex 终验通过，任务才进入完成态。

### 1.2 核心架构决策正式拍板（写入 `con_hf/SPEC_DECISIONS.md` D-01 ~ D-12）

针对上述 9 大缺口与工程边界，做出如下 **12 项强制性架构裁定（D-01 ~ D-12）**，作为全平台不可逾越的上位法基准：

1. **【裁定 D-01（Codex 编排侧适配器选型）】**：电脑端统一使用 **`codex-a2a`** 作为 A2A 协议插座。`codex-a2a` 在同一进程内同时提供 **A2A Server**（仅绑定 `127.0.0.1:8000` 供本地自检）与 **内置 A2A Client**（向 Codex 会话注入出站 `a2a_call` 工具及 CLI `codex-a2a call` 入口），严禁在 Codex 侧手写散乱的裸脚本替代标准适配器。
2. **【裁定 D-02（Pi 执行侧适配器选型）】**：手机 Termux 端统一使用 **`@bacnh85/pi-a2a`** 扩展作为 A2A Server 运行时（监听 `:9910`）。严格遵循 A2A Protocol v1.0，通过 `GET /.well-known/agent-card.json` 暴露能力清单，通过 `POST /` 接收 JSON-RPC 2.0 方法（`SendMessage`、`SendStreamingMessage`、`GetTask`、`CancelTask`）。
3. **【裁定 D-03（零信任 Token 认证与网卡绑定锁）】**：手机端 `@bacnh85/pi-a2a` 默认绑定 `127.0.0.1:9910`。**唯有当 `~/.pi/agent/settings.json` 中同时配置了非空的 `server.peerTokens`（Token 熵值 $\ge 192\text{ bits}$，即 `a2a_sec_` + 48 位十六进制字符）与 `server.trustedPeers: ["codex"]`，且 `allowAllUsers: false` 时，才允许将 `server.host` 放宽为 `"0.0.0.0"`**。
4. **【裁定 D-04（单向控制流铁律）】**：确立 **“Codex / 18787 规划、传文件与验收（Master） ──► Pi 本地自治执行与回传（Worker）”** 的绝对单向控制流。本工程阶段在 Pi 侧配置中严禁配置指向电脑的出站 Peer，彻底杜绝双向递归委派死锁。
5. **【裁定 D-05（Android Termux P0 级保活五件套）】**：手机端算力节点必须同时满足 5 项保活条件方可进入可用状态：① 持有 `termux-wake-lock`；② Android 系统设置将 Termux 电池策略设为“无限制（Unrestricted）”；③ 设备保持物理供电；④ 服务运行于命名 `tmux` 会话（`pi-a2a`）内；⑤ Android 12+ 设备通过 ADB 或无线调试关闭幻影进程限制（`max_phantom_processes=2147483647`），且在 `settings.json` 中锁死 `maxConcurrent: 2`。
6. **【裁定 D-06（阻塞与异步双模任务状态机契约）】**：
   * Pi 侧阻塞窗口锁死 `replyTimeoutSec: 300`（5 分钟），客户端 `timeouts.send` 锁死 `360000`（360 秒）。
   * 凡预估耗时 $\le 60\text{s}$ 的轻量探针任务，可使用阻塞式 `SendMessage`（`returnImmediately: false`）一步拿回 `completed` 状态与 `Artifact`。
   * 凡预估耗时 $> 60\text{s}$ 的构建/生信运行任务，Codex 侧一律使用异步派发（`returnImmediately: true`）或超时自动转入 `GetTask` 指数退避轮询（`5s -> 10s -> 20s -> 30s` 封顶），严禁在未调用 `GetTask` / `CancelTask` 确认前盲目重发写任务。
7. **【裁定 D-07（Tailscale 专网直连与代理豁免铁律）】**：严禁在公网路由器对 `:9910` 或 `:9911` 做端口映射或 DMZ 暴露。双端跨网通信唯一锚定 **Tailscale 虚拟局域网（`100.64.0.0/10`）**；电脑端 `codex-a2a` 与 `18787` 服务端必须显式导出 `NO_PROXY="127.0.0.1,localhost,100.64.0.0/10,<PI_TAILSCALE_IP>"` 并禁用 HTTP Agent 代理转发，防止本地 `7890` 代理劫持。
8. **【裁定 D-08（双平面物理目录与 Termux 原生文件系统隔离）】**：
   * 电脑编排面唯一锚定 `CODEX_WORKSPACE_ROOT`（包含 `src/`、`ops/`、`tests/`、`con_hf/`、`local_projects/`）。
   * 手机执行面唯一锚定 Termux 原生分区 `/data/data/com.termux/files/home/workspace/`（简写 `$HOME/workspace/`，以及容器算力面 `/mnt/ssd/bio_data/`），**严禁在 `/sdcard/` 或 `/storage/emulated/0/` 下创建任何代码工作区**。
9. **【裁定 D-09（结构化 Artifact 验收入库标准）】**：Pi 执行任何任务后，回传的 `Artifact` 必须包含 `task_id`、`step_id`、`idempotent_status`、`executed_at`、`workspace_dir`、`script_path`、`script_sha256`、`inputs_sha256`、`exit_code`、`duration_sec`、`log_file`、`changed_files`、`stdout_summary`。`changed_files` 的每项必须包含相对路径、64 位 SHA256 和 action，使 Codex 无需二次远程查看即可判定任务成败。
10. **【裁定 D-10（密钥零落盘入库与双层台账审计）】**：所有 Peer Token 严禁硬编码进 Git 追踪文件；所有架构变更、模型切换、任务派发与故障修复必须实时追加至 `con_hf/ledger/*.jsonl` 与 Pi 侧 `childTranscripts`。
11. **【裁定 D-11（传算分离、幂等断点防重跑 `.lock/.done` 与 Strict Runner 只读母版铁律 —— 根治 G8）】**：
    * **传算分离**：大体积数据与构建好的脚本（`.R` / `.py` / `.sh`）由电脑端通过确定性同步通道（`rsync` / `scp` / `sync_and_verify_remote.ps1`）先行推送至手机端只读脚本区并完成 SHA256 对账；A2A 通道**仅传输任务编排指令与轻量验收 Artifact（`< 4MB`）**。
    * **幂等防重跑包装器（`ops/pi_idempotent_runner.sh`）**：Pi Agent 执行任何预构建步骤时，必须调用 `pi_idempotent_runner.sh --project <id> [--task-id <id>] --step <step_id> --script <path> [--inputs <csv>] [--outputs <csv>]`。包装器用 `mkdir` 原子维护 `.step_<id>.lock.d/owner.json`，记录 runner PID、`child_pid`、`child_pgid`、任务 ID、脚本哈希、输入哈希和启动时间。子任务通过 `setsid` 独立进程组运行；TERM、INT、HUP 整组回收；runner 被 SIGKILL 后，新调用等待仍存活 child，并在产物有效时恢复 `.done`。`.step_<id>.done` 同时校验脚本、输入和产物 SHA256，有效命中时在 `0.5s` 门槛内返回缓存 Artifact。
    * **Strict Runner 只读约束与日志削峰**：预构建脚本目录对 Pi Agent 锁死只读权限（`chmod a-w`）；Pi Agent 严禁擅自修改已验脚本源码（如严禁改动 `seed=20261013` 或 `tip.length=0`）；脚本完整输出重定向至 `system_logs/<step_id>.log`，回传时仅将最后 12 行压平，并按 UTF-8 字符截取 320 字符的 `stdout_summary`。PNG 产物同时校验魔数头和 IEND 尾，截断图像不得写入 `.done`。
12. **【裁定 D-12（BioanalysDesktop `18787` 编排面 Pi Agent 观测与模型管控中心 —— 根治 G9）】**：
    * 在手机端部署与 `:9910` 共享同一 `peerTokens.codex` 密钥的轻量级遥测 Sidecar 服务 **`pi_telemetry_sidecar.py`（监听 `:9911`）**，实时采集 `~/.pi/agent/settings.json`、`~/.pi/agent/transcripts/*.jsonl`、`pi_a2a_daemon.log` 及 Termux 硬件状态（内存、电量、温度、WakeLock）。
    * 在 BioanalysDesktop `18787` 服务端挂载 `/api/pi-agent/{overview,logs,model,ping}` 代理路由，并在前端工作台挂载 `mod-pi-observability` 四联监控面板（调用信息台账、实时双流日志、模型白名单热切换、分模型 Token/成本统计图表）。

## 第二部分：微内核插座架构设计（Zero-Touch Host + 三层单向依赖）

### 2.1 三层物理目录与单向依赖拓扑（含 `mod-pi-observability` 与幂等执行底座）

我们将整个双 Agent 协作工程与 `BioanalysDesktop (18787)` 无缝映射为 **三层微内核插座架构**，严格遵循 `Mod（业务卡带层） ──► Engine（共享能力引擎层） ──► Core（宿主微内核层）` 的单向依赖：

```text
<工作区根 codex-pi-a2a-workbench/>
│
├── 00.最高技术纲领-20261028.txt                  # 【1 份平台最高宪法】全平台 SSOT 契约与禁区 (v1.1.0)
│
├── src/
│   ├── core/                                    # 【第一层：宿主微内核层 (Zero-Touch Host)】对具体业务与设备无知
│   │   ├── ModLoader.ts                         # 自动扫描并挂载 src/mods/*/manifest.ts 模块卡带
```
