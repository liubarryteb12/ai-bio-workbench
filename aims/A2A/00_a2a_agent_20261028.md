## 第一部分：对双 Agent 跨端协作痛点的深度复盘与架构诊断

### 1.1 为什么必须采用“A2A 协议 + 微内核插座 + 1+N×3 文档体系”，而非传统 MCP 逐命令穿透？

在“电脑 Codex + 手机 Termux Pi Agent”双端协同场景中，传统做法是让电脑端大模型通过 SSH/MCP 工具直接逐条下发 Shell 指令操控手机。然而实测工程表明，这种“单大脑 + 远程哑终端”耦合模式存在致命缺陷，并在实际部署中暴露出 **7 大结构性工程缺口（G1 ~ G7）**。

从系统架构师视角审视，**MCP（Model Context Protocol）解决的是“单个 Agent 如何调用哑工具（Tool/Function）”**，而 **A2A（Agent-to-Agent Protocol v1.0）解决的是“两个拥有独立上下文、独立推理循环与本地工具链的对等或主从 Agent 如何进行工作委派与成果交接”**。将 A2A 协议纳入微内核插座架构，可一次性根治以下 7 大缺口：

| 缺口编号 | 现存具体工程问题（实测暴露的痛点与风险） | 传统耦合/粗放架构的病灶根源 | 微内核插座 + A2A v1.0 + 1+N×3 体系的根治方案 |
| :--- | :--- | :--- | :--- |
| **G1：网卡暴露与无鉴权裸奔风险** | `@bacnh85/pi-a2a` 若直接将 `server.host` 从 `127.0.0.1` 改为 `0.0.0.0` 而未配置 `peerTokens`，局域网或虚拟网内任意节点均可向 `:9910` 发送 `SendMessage` 驱动 Pi 执行任意 Shell。 | 网卡绑定配置与鉴权字典缺乏编译期/启动期联动锁，安全策略沦为人工口头约定。 | 立项 **D-03** 与 `security-audit-engine`：强制实施“零信任绑定守卫”，启动脚本与 `ModManifest` 双重校验 `host === "0.0.0.0"` 时 `peerTokens` 必须非空且长度 $\ge 32$ 字符，否则直接拒绝拉起并退出码 `2`。 |
| **G2：Android Doze 与幻影进程杀手（Phantom Process Killer）导致后台静默暴毙** | 手机息屏 3~5 分钟或算力负载升高时，Termux 内的 Node.js（Pi）与子进程被 Android 12+ 的 `PhantomProcessList`（默认上限 32 个子进程）或 Doze 电量优化静默杀死（`SIGKILL 9`），导致电脑端 `a2a_call` 出现 `Connection reset by peer`。 | 仅启动了 Pi 进程，未将 Android 底层电源锁、系统级 Phantom 阈值豁免与 `tmux` 守护纳入工程底座。 | 立项 **D-05** 与 `mod-a2a-network-keepalive`：强制落地 **Android 保活五件套**（`termux-wake-lock` + 电池“无限制” + 物理插电 + `tmux` 托管 + ADB 豁免 `settings_enable_monitor_phantom_procs=false`），并配守护巡检脚本。 |
| **G3：长任务阻塞超时（>300s）导致 HTTP 断连与孤儿任务失控** | 当 Codex 委派耗时 $> 300\text{s}$ 的全量编译或测试任务时，阻塞式 `SendMessage` 触发 `replyTimeoutSec: 300` 超时断开，但手机端 Pi 仍在后台盲目修改文件，Codex 重试时引发并发写冲突。 | 未区分“短平快同步阻塞任务”与“长周期异步轮询任务”的协议状态机边界，缺少 `GetTask` / `CancelTask` 闭环。 | 立项 **D-06** 与 `a2a-rpc-engine`：确立 **双模任务状态机**——预估 $\le 240\text{s}$ 任务走同步 `SendMessage`；超时或长任务自动转入基于 `taskId` 的 `GetTask` 指数退避轮询（上限 `asyncTimeoutSec: 86400`），异常中止时显式发送 `CancelTask` 回收锁。 |
| **G4：本地系统代理（如 7890）劫持 Tailscale 虚拟网流量导致 502/Timeout** | 电脑端开启 Clash/V2Ray 等系统代理（`HTTP_PROXY=127.0.0.1:7890`）时，`codex-a2a` 发往手机 Tailscale IP（`100.x.y.z:9910`）或本地 `127.0.0.1:8000` 的请求被代理软件劫持，返回 `502 Bad Gateway`。 | 出站 HTTP 客户端未显式剥离内网与 CGNAT（`100.64.0.0/10`）网段的代理环境变量。 | 立项 **D-07**：在 `transport-keepalive-engine` 与启动环境中强制锁死 `NO_PROXY="127.0.0.1,localhost,100.64.0.0/10,<pi-tailscale-ip>"`，确保 A2A 报文 100% 走 Tailscale WireGuard 隧道直连。 |
| **G5：手机存储路径误入 `/sdcard` 引发权限崩溃与 I/O 极度劣化** | Pi Agent 若在 `/sdcard/`（Android FUSE / sdcardfs 挂载层）下执行 `git`、`npm install` 或 `chmod +x`，会因不支持 POSIX 权限位与软链接而全面报错，且 I/O 延迟飙升 10 倍以上。 | 未对手机端工作区路径设置合法根守卫（`PathGuard`）。 | 立项 **D-08**：手机端工作区唯一锚定 Termux 原生 `ext4`/`f2fs` 分区 `$HOME/workspace/`（即 `/data/data/com.termux/files/home/workspace/`），由 `PathGuard` 拦截一切指向 `/sdcard` 或 `/storage/emulated` 的越界写入。 |
| **G6：Artifact 回传结构非标与大文件撑爆 JSON-RPC 内存** | Pi 执行完毕后仅返回口语化聊天文本，缺少文件 SHA256 对账头、Git Diff 与退出码；或者试图将数十 MB 的二进制产物塞入单个 JSON-RPC 响应体导致 OOM。 | 缺少强制性的 `A2AArtifactContract` 组装器与大小分级传输策略。 | 立项 **D-09** 与 `mod-a2a-artifact-audit`：强制 Pi 回传结构化三联 Artifact（① `execution_summary.json` 含退出码与耗时；② `changes.diff` 含代码变更；③ `checksums.sha256`），单报文文本上限锁死 `4MB`。 |
| **G7：双端会话记录与工程台账缺失，故障无法溯源** | 跨端任务失败时，不知道是网络闪断、鉴权拒绝、还是 Pi 内部工具报错；修改配置后无历史台账可查。 | 缺乏 `childTranscripts` 落盘审计与双层五类追加式 JSONL 工程台账。 | 立项 **D-10**：开启 Pi 侧 `childTranscripts: true`（保留 7 天），并在工程根目录建立 `con_hf/ledger/{actions,changes,errors,fixes,pitfalls}.jsonl` 双层审计台账。 |

### 1.2 核心架构决策正式拍板（写入 `con_hf/SPEC_DECISIONS.md` D-01 ~ D-10）

针对上述 7 大缺口与工程边界，做出如下 **10 项强制性架构裁定（D-01 ~ D-10）**，作为全平台不可逾越的上位法基准：

1. **【裁定 D-01（Codex 编排侧适配器选型）】**：电脑端统一使用 **`codex-a2a`** 作为 A2A 协议插座。`codex-a2a` 在同一进程内同时提供 **A2A Server**（仅绑定 `127.0.0.1:8000` 供本地自检）与 **内置 A2A Client**（向 Codex 会话注入出站 `a2a_call` 工具及 CLI `codex-a2a call` 入口），严禁在 Codex 侧手写散乱的 curl 脚本替代标准适配器。
2. **【裁定 D-02（Pi 执行侧适配器选型）】**：手机 Termux 端统一使用 **`@bacnh85/pi-a2a`** 扩展作为 A2A Server 运行时。严格遵循 A2A Protocol v1.0，通过 `GET /.well-known/agent-card.json` 暴露能力清单，通过 `POST /` 接收 JSON-RPC 2.0 方法（`SendMessage`、`SendStreamingMessage`、`GetTask`、`CancelTask`）。
3. **【裁定 D-03（零信任 Token 认证与网卡绑定锁）】**：手机端 `@bacnh85/pi-a2a` 默认绑定 `127.0.0.1:9910`。**唯有当 `~/.pi/agent/settings.json` 中同时配置了非空的 `server.peerTokens`（Token 熵值 $\ge 192\text{ bits}$，即 48 位十六进制字符）与 `server.trustedPeers: ["codex"]`，且 `allowAllUsers: false` 时，才允许将 `server.host` 放宽为 `"0.0.0.0"`**。
4. **【裁定 D-04（单向控制流铁律）】**：确立 **“Codex 规划与验收（Master） ──► Pi 自主执行与回传（Worker）”** 的绝对单向控制流。即使 `@bacnh85/pi-a2a` 支持出站调用，本工程阶段在 Pi 侧配置中严禁配置指向电脑的出站 Peer，彻底杜绝双向递归委派死锁。
5. **【裁定 D-05（Android Termux P0 级保活五件套）】**：手机端算力节点必须同时满足 5 项保活条件方可进入可用状态：① 持有 `termux-wake-lock`；② Android 系统设置将 Termux 电池策略设为“无限制（Unrestricted）”；③ 设备保持物理供电；④ 服务运行于命名 `tmux` 会话（`pi-a2a`）内；⑤ Android 12+ 设备通过 ADB 或无线调试关闭幻影进程限制（`max_phantom_processes=2147483647`），且在 `settings.json` 中锁死 `maxConcurrent: 2`。
6. **【裁定 D-06（阻塞与异步双模任务状态机契约）】**：
   * Pi 侧阻塞窗口锁死 `replyTimeoutSec: 300`（5 分钟），客户端 `timeouts.send` 锁死 `360000`（360 秒，留出 60 秒网络与序列化缓冲）。
   * 凡预估耗时 $\le 240\text{s}$ 的原子任务，使用阻塞式 `SendMessage` 一步拿回 `completed` 状态与 `Artifact`。
   * 凡预估耗时 $> 240\text{s}$ 的重型任务（如全量 pytest、编译构建），或阻塞等待满 `300s` 返回 `working` 状态的任务，Codex 侧必须转入 `GetTask` 轮询模式（轮询间隔按 `5s -> 10s -> 20s -> 30s` 封顶退避），严禁在未调用 `CancelTask` 确认前重复派发相同写任务。
7. **【裁定 D-07（Tailscale 专网直连与代理豁免铁律）】**：严禁在公网路由器对 `:9910` 做端口映射或 DMZ 暴露。双端跨网通信唯一锚定 **Tailscale 虚拟局域网（`100.64.0.0/10`）**；电脑端启动 `codex-a2a` 前必须显式导出 `NO_PROXY="127.0.0.1,localhost,100.64.0.0/10,<PI_TAILSCALE_IP>"`，防止本地代理劫持。
8. **【裁定 D-08（双平面物理目录与 Termux 原生文件系统隔离）】**：
   * 电脑编排面唯一锚定 `CODEX_WORKSPACE_ROOT`（包含 `src/`、`ops/`、`tests/`、`con_hf/`、`local_projects/`）。
   * 手机执行面唯一锚定 Termux 原生分区 `/data/data/com.termux/files/home/workspace/`（简写 `$HOME/workspace/`），**严禁在 `/sdcard/` 或 `/storage/emulated/0/` 下创建任何代码工作区**。
9. **【裁定 D-09（结构化 Artifact 验收入库标准）】**：Pi 执行任何修改或验证任务后，回传的 `Artifact` 必须包含结构化机器可读摘要（含 `exit_code`、`changed_files`、`sha256_map`、`stdout_tail`），使 Codex 无需二次远程查看即可 100% 判定任务成败。
10. **【裁定 D-10（密钥零落盘入库与双层台账审计）】**：所有 Peer Token 严禁硬编码进 Git 追踪文件（真实值仅存于环境变量或被 `.gitignore` 忽略的运行时文件，仓库内仅保留 `.example` 模板）；所有架构变更、故障与修复必须实时追加至 `con_hf/ledger/*.jsonl` 与 Pi 侧 `childTranscripts`。

## 第二部分：微内核插座架构设计（Zero-Touch Host + 三层单向依赖）

### 2.1 三层物理目录与单向依赖拓扑

为避免把脚本、配置、测试与业务模块混成一团乱麻，我们将整個双 Agent 协作工程严格映射为 **三层微内核插座架构**，遵循 `Mod（业务卡带层） ──► Engine（共享能力引擎层） ──► Core（宿主微内核层）` 的严格单向依赖，严禁反向引用或跨 Mod 横向耦合：
