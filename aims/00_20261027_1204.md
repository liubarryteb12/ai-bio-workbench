### 2.2 四大核心插座机制设计细节

1. **自动卡带加载器（`ModLoader`）**：
   * 18787 服务端与前端启动时，自动扫描 `src/mods/*/manifest.ts`（Node 端通过 `fs.readdirSync` + 动态 `import()`，前端 Vite 通过 `import.meta.glob('/src/mods/*/manifest.ts', { eager: true })`）。
   * 拔掉任意一个 `mod-*` 文件夹（例如拔掉 `mod-line3-spatial`），系统无需修改任何一行宿主路由、自检或打包代码，自动隐藏 Line 3 选项并 100% 正常编译运行。
2. **UI 扩展插槽管理器（`SlotManager`）**：
   * 预设 6 个标准插槽：`portal.step-line-selector`（门户选线）、`portal.step-figure-picker`（门户选图）、`portal.result-gallery`（门户结果预览）、`workbench.pipeline-tree`（18787 步骤树）、`workbench.selfcheck-cards`（18787 五维自检扩展卡）、`workbench.studio-preview`（18787 三栏预览）。
3. **跨模块只读能力总线（`CapabilityBus`）**：
   * `mod-figure-templates` 需要校验某个分析步骤是否产出特定 `.tsv` 表时，严禁直接 `import` `mod-line1-bulk` 内部文件，而是调用 `CapabilityBus.query('pipeline.getStepOutputs', { line: 'line1_bulk', step: 'l1_deg_limma' })`。
4. **自声明存储与动态打包路由（`ledgerStores` & `deliverableCollectors`）**：
   * 每个 Mod 在 `manifest.ts` 中声明自己产出的文件匹配模式（`outputGlobs`）与适配代码目录（`adaptCodeDir`），`sync-engine` 的 `build_client_report.py` 自动遍历已挂载 Mod 的声明进行收集、计算 `CHECKSUMS.sha256` 并执行 Ed25519 签名。

三、 全平台统一度量衡与物理目录隔离标准
1. 时间与随机种子标准：

2. 数值与图像精度标准：
   - 跨语言（R <-> Python）数值矩阵与 CSV/TSV 导出锁死 **17 位有效数字精度（bit-exact）**，UTF-8 无 BOM 编码。
