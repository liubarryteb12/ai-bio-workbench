# 分册 02 · 环境准备与日常运行运维手册 (Environment & Operations Manual)

> **文档性质**：开发机部署、K40 物理机维护、网络链路映射与日常操作字典  
> **基线版本**：2026-11-07

## 一、运行环境规格要求

### 1. 本地控制面（Windows PC 开发机）
- **操作系统**：Windows 10 / 11 64-bit；
- **Node.js**：Node >= 22（生产与 CI 推荐 22+，本机实测验证版本：**Node v24.19.0**，路径 `D:\node-v2.4\node.exe`）；
- **PowerShell**：PowerShell 7+（`pwsh.exe`），用于本地运维与自动化门禁；
- **Git**：Git for Windows 2.40+（`D:\Git\bin\git.exe`）；
- **Python**：Python 3.10+（用于运行标定、门禁与报告渲染器）。

### 2. 远端算力面（使用者自备）
- **设备型号**：由使用者按 `docs/COMPUTE_INTERFACE.md` 配置，不在仓库记录；
- **宿主环境**：基础用户空间可执行命令，具备服务监管能力；
- **容器环境**：Linux 容器，名称由 `BIO_PROOT_DISTRO` 指定；
- **生信 Python 环境**：专用科学虚拟环境 `/root/venvs/bio-py/bin/python3`，预装 Scanpy 1.12.4、Squidpy 1.8.3、AnnData、SciPy、NetworkX 等；
- **生信 R 环境**：R 4.5.3，预装 DESeq2、limma、clusterProfiler、WGCNA、Seurat 等；
- **专用存储挂载**：外部高速 SSD 挂载于 `/mnt/ssd/bio_data/`（挂载点权限严格对齐）。

## 二、网络链路与 SSH 隧道配置

PC 与 K40 之间通过 USB 数据线连接，由 ADB 完成本地回环端口映射。

### 1. ADB 端口映射规则
```powershell
# 检查 ADB 设备在线状态
adb devices

# 建立三条关键端口转发
adb forward tcp:10022 tcp:10022   # PROOT Ubuntu 容器 SSH (执行面)
adb forward tcp:8022  tcp:8022    # Termux 宿主 SSH (管理面)
adb forward tcp:9910  tcp:9910    # Pi Agent 遥测通道 1
adb forward tcp:9911  tcp:9911    # Pi Agent 遥测通道 2
```

### 2. 本地 SSH 配置文件 (`~/.ssh/config`)
本地开发机 `C:\Users\<用户名>\.ssh\config` 必须具备以下别名配置：
```sshconfig
# K40 PROOT Ubuntu 容器执行面 (生信重计算唯一落点)
Host k40-ubuntu
    HostName 127.0.0.1
    Port 10022
    User root
    IdentityFile ~/.ssh/id_ed25519
    StrictHostKeyChecking no
    UserKnownHostsFile /dev/null
    ConnectTimeout 15

# K40 Termux 宿主管理面 (守护进程与系统观测)
Host k40
    HostName 127.0.0.1
    Port 8022
    User u0_a234
    IdentityFile ~/.ssh/id_ed25519
    StrictHostKeyChecking no
    UserKnownHostsFile /dev/null
    ConnectTimeout 15
```

### 3. 一键链路探活脚本
```powershell
Set-Location 'D:\00.AIagent\codespace\AI辅助生信分析流程工作台'
pwsh -File ops/00_link_check.ps1
```
该脚本将按序执行四阶段自检：
1. **Phase 1**：ADB 设备在线检测；
2. **Phase 2**：ADB Forward 端口映射验证；
3. **Phase 3**：SSH 容器连接握手与 `echo CONTAINER_OK`；
4. **Phase 4**：`/mnt/ssd/bio_data` SSD 挂载区读写探活。

## 三、日常服务启停与构建指南

### 1. 启动桌面端管理工作台 (`BioanalysDesktop`)
```powershell
Set-Location 'D:\00.AIagent\codespace\AI辅助生信分析流程工作台\BioanalysDesktop'

# 同时启动后端与前端（推荐开发模式）
npm run dev
# 访问地址：http://127.0.0.1:5173 (前端)；http://127.0.0.1:18787 (后端)

# 单独启动后端服务
npm run dev:server

# 单独启动前端服务
npm run dev:web

# 生产环境完整构建与打包
npm run build       # Vite 生产编译打包入 dist/
npm start           # 运行生产模式后端
```

### 2. 启动客户需求提交门户 (`portal`)
```powershell
Set-Location 'D:\00.AIagent\codespace\AI辅助生信分析流程工作台'
node portal/serve.mjs
# 访问地址：http://127.0.0.1:8080
```

### 3. 环境变量与安全配置参数
| 环境变量名 | 作用 | 默认值 | 安全与行为约束 |
|---|---|---|---|
| `BAD_PORT` | BioanalysDesktop 后端端口 | `18787` | 仅监听本地回环 `127.0.0.1` |
| `BAD_AUTH_USER` / `BAD_AUTH_PASS` | 管理端 Basic 认证账号口令 | 自动生成动态口令 | 若未传环境变量，启动时自动生成并写入 `.auth_runtime.json`（退出即焚） |
| `BIO_COMPUTE_ADAPTER` | 算力适配器模式 | `ssh` | `ssh`=真机下发；`mock`=演示与单测模式 |
| `BIO_UPLOAD_TTL_HOURS` | 上传分片临时文件留存 TTL | `24` 小时 | 超期自动垃圾回收 |
| `BIO_UPLOAD_QUOTA_BYTES` | 分片上传总缓存配额 | `10737418240` (10 GiB) | 超限时按 mtime 最旧优先淘汰非活跃会话 |
| `BIO_IDEMPOTENT_LOCK` | 算力包装器步骤幂等互斥锁开关 | `1` (开启) | `0`=紧急排障时临时旁路互斥锁 |

## 四、算力面脚本同步与部署规范

为确保仓库代码与 K40 设备上的执行母版绝对同源，**严禁使用手工 SSH 贴代码方式修改远端脚本**。必须走标准部署流水线：

```powershell
Set-Location 'D:\00.AIagent\codespace\AI辅助生信分析流程工作台'

# 1. 对账比对：检查仓库与 K40 远端母版差异
& 'D:/node-v2.4/node.exe' ops/k40_script_parity.mjs
# 期望输出：K40_SCRIPT_PARITY_OK 双向集合恒等 + 逐字节一致（57 个脚本）

# 2. 强制定向同步指定流水线母版至 K40
pwsh -File ops/06_deploy_scripts.ps1 -Line line1_bulk    -Force
pwsh -File ops/06_deploy_scripts.ps1 -Line line2_scrna   -Force
pwsh -File ops/06_deploy_scripts.ps1 -Line line3_spatial -Force
```

部署脚本自动执行以下硬性保障：
- **LF 行尾自动归一化**（杜绝 Windows CRLF 导致 Linux 报 `: command not found`）；
- **POSIX 权限强制 755**；
- **部署后 SHA256 双向哈希二次校验**。

## 五、典型故障排查与避坑指南

### 1. Windows 原生 OpenSSH 退出码 255 假死
- **现象**：`proc.js` 调起 `ssh` 或命令行 `ssh k40-ubuntu` 瞬间退出，退出码 255，无 stderr；
- **根因**：Windows 原生 OpenSSH 必须依赖环境变量 `%SystemRoot%`（如 `C:\Windows`）来加载 Winsock 底层库。如果 Node 子进程未继承该变量，SSH 握手即刻崩溃；
- **工程防线**：`BioanalysDesktop/server/proc.js` 已内置 `childEnv` 兜底，自动补齐 `SystemRoot`。接手人写临时脚本时必须注意传递完整的系统环境变量。

### 2. ADB 沙箱启动 `Cannot mkdir '\.android': Permission denied`
- **现象**：在受限沙箱或特定受限账户下调起 `adb.exe` 报 `0xC0000142` 崩溃；
- **根因**：ADB 启动时默认尝试向系统盘根目录创建 `\.android` 缓存；
- **处理原则**：测试套件中的 `link.test.js`、`proc.test.js` 若因沙箱权限报红，属于环境信号而非代码回归。提权后重跑即可全绿。

### 3. Android 13 幽灵进程杀手 (Phantom Process Killer)
- **现象**：K40 长耗时任务跑 20~30 分钟突然断开，Termux 后台全部消失；
- **防线措施**：必须在手机宿主侧通过 ADB 运行系统级保活指令：
  ```bash
  adb shell "/system/bin/device_config put activity_manager max_phantom_processes 2147483647"
  ```
- 详细保活配置详见 [`docs/termux_keepalive.md`](../docs/termux_keepalive.md)。

### 4. 电池温度 90°C 热节流防死锁
- **防线措施**：`ops/run_throttled_task.sh` 在执行高负载计算前会实时读取手机电池温度探针 `/sys/class/power_supply/battery/temp`。温度达到 85°C 时主动降低 nice 优先级，达到 90°C 时硬熔断挂起，避免通用 ARM64 处理器 硬件高温保护导致内核直接强行掉电死机。
