# 红米 K40 Linux 适配优化与运行效率提升 — 推进计划（2026-10-20）

> 性质：基础设施加固计划（非分析任务）。依据：`AGENTS.md` 开工规则 + 用户本轮指令
> 「在安全、稳定情况下优化手机对 Linux 系统的适配，提高其在手机上的运行效率，自拟计划并自行推动」。
> 边界：`reference/` 只读不动；「四不改」冻结区（`BioanalysDesktop` 框架、`ops/` 既有文件、`src/` 母版脚本）
> 不改；`aims/aims.txt` 契约变更只提交数据与建议，由用户拍板。

## 一、目标（可验收）

1. **适配**：把手机侧 Linux 环境（Termux 底座 + Ubuntu 容器）与项目运行要求之间的**全部偏差查清、记录、
   处置**——发现的缺陷要么修复（可回滚），要么有明确缓解措施；开机自启 / 保活 / 服务监管链完整可复验。
2. **效率**：用固定 seed 的基准任务，实测「当前配置 vs 候选配置」的耗时与温度曲线；若存在**明确更优且
   不突破安全边界**的配置，落地到容器侧全局配置；涉及 aims 契约条款的，整理实测数据交用户拍板。
3. **沉淀**：结论写入 `con_hf/` 台账与 `docs/`，后续会话可按文档恢复。

## 二、基线侦查（已完成，全部实测）

链路现状：设备 `3a3e1f52` 在线；`ssh k40` / `ssh k40-ubuntu` 双通；Termux 五服务（sshd / crond /
ssh-agent / ubuntu-sshd / bio-watchdog）全 `run`，log 子服务全 `run`（R13 LOGDIR 修复生效）；
手机 up 6 天，负载 0.31，温度 ~33°C；容器 12GB 内存（Swap 8GB zram），数据面 226G 分区剩 65%。

**CPU 拓扑实测**（骁龙 870，`/sys/devices/system/cpu/`）：

| 核 | 角色 | 最高频率 | 状态 |
|---|---|---|---|
| cpu0-3 | A55 小核 | 1.80 GHz | 可用（`taskset -c 3` OK） |
| cpu4-6 | A77 大核 | 2.42 GHz | 可用（`taskset -c 4-6` OK，实测绑定完整） |
| cpu7 | A77 Prime | 3.19 GHz | **单绑恒失败** |

**关键发现 F1（CPU 隔离语义）**：`taskset -c 7` / `-c 5` / `-c 5,7` 恒报 `Invalid argument`；
而 `5,6` / `7,6` / `4,5,6` 全部成功且绑定完整（实测子进程 `Cpus_allowed_list=4-6`）。
⇒ 语义 = 「只含被隔离核的集合被拒，含至少一个非隔离核的集合放行」= 典型部分核隔离
（isolcpus / MIUI 定制）。含义：
- aims 契约「绑大核 4,5,6」**实测成立**（10/10 稳定，掩码完整 4-6）；
- 「空置超大核 7 防发热」实际是**被迫不可用**而非主动策略——Prime 3.19GHz 对单线程任务是
  闲置资源，但是否启用属 aims 契约（§六「空置超大核 7 防发热降频」），**不自行改，出数据再说**。

**关键发现 F2（绑核失败=任务失败的健壮性缺口）**：`ops/run_throttled_task.sh`（冻结文件）中
`taskset -c 4,5,6` 若在 Android 动态调整下失败（EINVAL），`set +e` 段会走完但 `EXIT_CODE≠0`
⇒ 台账记 `failed`，任务实际未执行。当前实测 4,5,6 稳定（10/10），风险未触发，但缺降级通道。

**关键发现 F3（线程封顶的生效面）**：`/etc/profile.d/bio_limits.sh`（3 线程封顶）只在登录 shell 生效；
`ssh k40-ubuntu 'cmd'` 一次性命令**不加载**。生效面 = 走 `run_throttled_task.sh` 的任务
（其显式 source）+ 交互登录。直跑命令的线程数=未封顶（默认可能吃满核）。

**关键发现 F4（动态性）**：首次采样某 ssh shell 亲和性为 `0-4,6`，其后 10 次采样全为 `0-7`
⇒ Android cpuset 存在动态调整，「可用核数」不是常量，配置策略需对此健壮。

## 三、分阶段计划

### 阶段 0：效率基准实测（无环境改动）

- B1：CPU 隔离语义确认——绑 4,5,6 跑 CPU 密集负载，`ps -o psr` 高频采样实际运行核分布
  （若 cpu5 从不被调度到，则「三大核」实际只有两大核在算）。
- B2：基准矩阵（固定 seed，R + Python 双语言，每配置 2 轮取稳定值，轮间 sleep 2s）：

  | 配置 | 绑核 | 线程 | 意图 |
  |---|---|---|---|
  | A | 无 | 3 | bio_limits 登录态现状 |
  | B | 4,5,6 | 3 | aims 契约现状（经 run_throttled_task） |
  | C | 4,6 | 2 | 剔除疑似隔离核 + 匹配线程 |
  | D | 4,6 | 3 | 只剔核不调线程 |
  | E | 0-7 | 3 | 放开全部核（对照） |
  | F | 4,5,6 | 4 | 试探超配（仅数据，不采用） |

  - R 基准：limma `lmFit + eBayes`，5000 基因 × 50 样本，`set.seed(20261013)`；
  - Python 基准：numpy 2000×2000 matmul ×5，`np.random.default_rng(20261013)`；
  - 同时每 3s 采样 `/sys/class/thermal/thermal_zone*/temp` 记峰值；负载期间 `ps -o psr` 0.5s 采样。
- 验收：每配置 2 轮 wall time 差 <10%（稳定性），输出 CSV + 一段数据结论。

### 阶段 1：适配修复与加固（手机侧系统层，全部可回滚）

- A1（依赖 B 结论）：若数据显示更优线程/绑核组合**在 aims 契约范围内**（如 C/D），更新容器
  `/etc/profile.d/bio_limits.sh` 与 `run_throttled_task.sh` 的**容器侧副本**（母本在 ops/ 冻结，
  只改设备侧部署副本并留 `.bak`；同时在本计划记「母本待用户拍板」）。
  若最优组合**突破契约**（如启用 cpu7），不动环境，数据写进结论交用户拍板。
- A2：容器 `/tmp` 可写性已确认（TMP_WRITABLE）——无需处理；Termux 侧 /tmp 只读（坑#65）
  在 boot 脚本中已规避，复核一遍无回归即可。
- A3：保活链复验（不重启手机）：`00_link_check.ps1` 四段 + 五服务 + 唤醒锁 + 故障注入
  （`sv down crond` → watchdog 49s 内拉起，与 2026-10-18 记录对齐）。
- A4：把 F1–F4 写进 `docs/`（新建 `docs/k40_cpu_affinity.md`：核拓扑、隔离语义、绑核策略、
  线程封顶生效面、健壮性注意事项），供后续所有会话引用。

### 阶段 2：回归与归档

- R1：基准复跑一次最优配置，确认耗时稳定。
- R2：`00_link_check.ps1` exit 0；五服务全 run；`ssh k40-ubuntu` CONTAINER_OK。
- R3：`con_hf/操作台账.md` 追加本条；`con_hf/handoff.md` 更新；`con_hf/踩坑台账.md` 记新坑
  （taskset 单绑隔离核 EINVAL 语义、profile.d 对一次性 ssh 命令不生效）。
- R4：真机 `adb reboot` 端到端验证（**需用户参与**：Android FBE 下重启后必须人工解锁一次，
  坑#85）——排在最后，仅当用户在场时执行；否则记为遗留。

## 四、需要用户参与的节点

1. 阶段 2 R4 真机重启（人工解锁）。
2. 若阶段 0/1 结论要求变更 aims 契约条款（绑核集合 / 线程数 / Prime 核启用），提交数据等拍板。

## 五、风险与约束

- 所有手机侧改动遵循「先备份 → 小改 → 实证 → 可回滚」；备份命名带日期。
- 不碰 `projects/default/` 数据面、不跑分析任务（本计划只做环境层）。
- 基准任务仅用合成数据 + 固定 seed，不产生任何业务产物。
- 本地零算力红线：R/Python 只在容器跑；本地只跑 ssh/scp/adb/pwsh/node。
- 长任务本地持有 ssh（`-o ServerAliveInterval=30`），不中途掐链路。
