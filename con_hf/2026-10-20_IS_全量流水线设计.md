# PRJ_20261019_IS_lactylation 全量分析流水线设计（2026-10-20）

> 背景：用户指出图件量远低于规范期望（21 vs 141），要求"先补分析数据再出全图，
> 设计好每一步的分析流程，上下游对接好"。本文档定义三线完整步骤链与数据流；
> 执行进度随跑随更。

## 总体架构

```
原始数据(GEO) → [线1 bulk: 母版全链路 + LRG 增量]
              → [线2 scrRNA: 桥接 scrna_deg.h5ad + 母版出图 + 我的增量]
              → [线3 spatial: 坐标重建 + 母版全链路 + 我的增量]
```

**执行原则**：
1. 母版脚本（`bin/<line>/<step>`，与 `src/` 同源 md5 一致）优先，保证图件命名/
   caption/口径与母版一致（figures.js 已登记全部母版图注）。
2. 母版跑不动的（内存/包兼容/数据缺失）用方案 A 沙盒脚本替代，**替代必须如实标注**。
3. 每步经 `ops/run_throttled_task.sh` 执行留台账；seed 全局 20261013。
4. 我的 LRG 专项分析（lrg_deg / ml_hub_lrg M1+M2 / immune_ssgsea / 五算法评分 /
   WGCNA / liana / 区域注释 / 目标基因）作为增量保留，与母版产物并存于 processed/。

2. STRING API 可达性未验证（ppi_string 可能失败）→ 失败则如实标注，不编图。
3. pyscenic 未装 → line2 SCENIC/virtual_knockout/dr 系列不跑（母版默认项目也未在
   本项目数据上验证过这些步骤）。

5. 所有"跳过/替代"必须在本文件与交付报告中如实登记，不得包装成完成。
