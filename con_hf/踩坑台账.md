#88【服务监管】`sv status sshd/crond/ssh-agent` 报 `run: xxx (pid N) ...; down: log: Ns, normally up, want up`，log 子服务无限 crash-loop，sshd 无实时日志可用
→ termux-services 自带的 svlogger 脚本用 `$LOGDIR` 拼日志目录（`mkdir -p "$LOGDIR/sv/$service"` + `exec svlogd -tt "$LOGDIR/sv/$service"`）。而 `$LOGDIR` 只在 boot 脚本自己 export 的那棵进程树里有，runsvdir 及其子孙 runit 服务的环境里没有这个变量 ⇒ `mkdir -p "/sv/xxx"` 失败 ⇒ svlogd 起不来。**boot 脚本 `export LOGDIR` 追不上已经存在的 runsvdir**，所以 reference 坑#87 里"export 后 sv up log 即可"的判断不完整、重启后仍复发。
→ 把手写绝对路径的 `log/run` 文件覆盖上去：`exec svlogd -tt /data/data/com.termux/files/usr/var/log/<svc>`。做法：`ops/01_fix_svlogger.ps1` + `ops/svlogger_{sshd,crond,ssh-agent}` 三个模板，先删软链（否则 scp 会跟随软链写 `/usr/share/termux-services/svlogger` 这个公共文件），再 scp + chmod 755 + `sv restart <svc>/log`。原软链指向备份在同目录 `<run>.origin`，可回滚。
→ 备注：修复后三服务主进程 pid 未变（8991/8992/8988），无服务中断；`/var/log/sshd/current` 有真实 Accepted publickey 记录，日志链路恢复。**ubuntu-sshd 的 log/run 本来就是手写绝对路径，所以它从未出过这个毛病。**

#89【自检脚本】`adb forward --list` 输出按 "serial local remote" 空格分隔，把 "tcp:8022 -> tcp:8022" 当匹配模式导致 forward 明明在位却判 FAIL
→ 自作聪明把空格替换成 ` -> ` 再匹配，adb 实际输出没这个箭头。
→ 直接用 `[regex]::Escape(local) + '\s+' + [regex]::Escape(remote)` 匹配。
→ 备注：本地 8022/10022 两条 forward 的 local 与 remote 相同，更容易看漏。**判断"在位"必须看命令真实输出格式，不能凭印象拼。**

#90【自检脚本】ssh 首次连接的 `Warning: Permanently added '...' to the list of known hosts.` 打到 stderr，2>&1 后混进 stdout，把服务状态解析弄出个"服务 Warning FAIL"
→ 非 tty 下 ssh 的 warning 与正常输出混流，按行解析时 warning 行被当成服务条目。
→ 对每类输出加特征过滤：服务行匹配 `^(sshd|crond|ssh-agent|ubuntu-sshd):`，探活行匹配 `^(TERMUX_OK|CONTAINER_OK|Rscript|Python)`。
→ 备注：**解析远端命令输出时，永远按特征白名单取行，不要假设输出干净。**

#91【服务入口】`/api/tasks/submit` 审计前置代码调用了未 import 的函数，一个跨线 POST 把整个服务打到崩溃（curl 报 ECONNRESET，连接被重置）

#94【PowerShell】ssh 输出赋给变量后 `-match` 返回的是匹配元素集合而不是布尔：没匹配时是空数组，字符串插值显示为空，`-notmatch` 判定被 warning 行带偏
→ `05_push_testdata.ps1` 首版 `$ubuntuMounted = ($r -match 'SSD_MOUNTED')`，`$r` 是 ssh 多行输出数组。`-match` 对集合求值时返回**匹配的元素**，不匹配返回空数组 `@()`。后果一：`"挂载: $ubuntuMounted"` 插值出空串（不是 False），显示误导；后果二：`$mkdirOut -notmatch 'DIRS_OK'` 在输出含 warning 行 + DIRS_OK 时返回 `@('Warning...')` 为 truthy，把成功判成 FAIL。
→ 全部改成显式布尔收敛：`[bool]($out | Where-Object { "$_" -match 'SSH_OK' })`；判定串取唯一值（SSH_OK/DIRS_OK/EXISTS），warning 行不会误撞。
→ 备注：**PowerShell 的 `-match` 从来不是布尔运算符**，对集合尤其不是。所有"远端输出里有某个标志行"的判断都要 `[bool](... | Where-Object {...})`，与 #90 的特征过滤是配套动作。

#95【proot 双面文件系统】容器（k40-ubuntu，proot-distro）看不见 Android 的 `/sdcard` 与 `/storage`；`/mnt/ssd` 在容器里是 rootfs 内的目录，与底座 Termux 看到的 `/mnt` 不是同一棵目录树
→ `05_push_testdata.ps1` 首版设计成"adb push 到 `/sdcard/bio_staging/` 再 ssh mv 到 SSD"，mv 跑在容器面，但容器里 `ls /sdcard/` 直接 `No such file or directory`。实测：容器 `ls /sdcard`、`ls /storage` 均不存在；proot-distro 用自己的 rootfs（`/mnt` 是 rootfs 自带的，开发期 mkdir 的 `/mnt/ssd/bio_data` 因此落在 eMMC 上）；底座 Termux 的 `/mnt` 是 Android 根的（product/rescue/runtime/sdcard/secure/user/vendor），**两个面的 `/mnt` 内容完全不同**。
→ 改法：传输路径换成 scp 经 ssh 隧道直送目标目录，无中转。scp 走 `~/.ssh/config` 已有别名，两个面都能直达；实测中文本地路径（`测试数据3（可用）\分组情况.txt`）与中文远端文件名双向都通（exit 0，字节数一致，测完已清理 `/tmp` 临时文件）。
→ 备注：**底座与容器是两套文件系统视图，任何"两面互见"的假设都要先实测。** 连带结论：SSD 必须挂载在容器面，计算在容器内跑，挂在 Android 面的盘容器看不见，数据送了也用不上。

#96【任务引擎】step 名含空格 → 台账文件名带空格 → 落盘命令 shell 重定向被拆断 → persistEntry 的 rejection 被 `void` 丢弃 → unhandled rejection 把整个 Node 服务打死（一次任务失败 = 服务下线）
→ 三病叠加，逐层拆：
  1. `buildLedgerFileName` 直接把 `step_name` 拼进文件名，step 是界面填的自由文本，含空格合法。落盘命令 `echo <b64> | base64 -d > /path/xxx_echo data_plane_ok_yyy.json` 被空格拆成两段，后半段被 base64 当成输入文件名（日志铁证：`base64: data_plane_ok_2b495454.json: No such file or directory`），台账丢失。
  2. `runTask` 的 exit handler 里 `void persistEntry(entry, lineId)`，`void` 把 promise 的 rejection 彻底丢弃。**Node 24 默认 unhandled rejection = throw，直接杀进程**，stack 指向 `run.js` 的 reject 行，但根因在调用方的 `void`。
  3. 提交接口不校验 step 字符集，`echo data_plane_ok` 这种"命令+参数"塞进 step 的输入能进到执行层（shellQuote 后变成"命令名含空格"，必然 command not found）。
→ 修法（TDD，先写红测）：`sanitizeFileNameSegment` 把文件名段收敛到 `[A-Za-z0-9._-]`（空格换下划线）；`buildLedgerWriteCommand` 抽成纯函数，远端路径整体加单引号（可单测）；`void` 改显式 `.catch()` 回报到 stderr（落盘失败不再杀服务，也不静默）；提交接口加 step 字符集校验提前 400。测试 57 → 60。
→ 备注：**`void promise` 在 Node 24 是埋雷**，任何 fire-and-forget 的 async 调用都要显式接 rejection。另注意"文件名拼进 shell 命令"是系统性风险面：所有拼远端命令的地方，路径都要引号包裹 + 段安全化，这次只修了台账一处，`task.js` 的 inputs/outputs 已有 shellQuote 覆盖。

#98【PowerShell】ssh 远端命令写在双引号里，`$PATH` 被 PowerShell 本地展开成空，远端收到畸形命令直接 exit 1 且无有用输出
→ 手动复验 probe_env 时写 `ssh k40-ubuntu "export PATH=...:$PATH && ..."`，PowerShell 双引号内的 `$PATH` 是本地变量（本机没有，展开为空），ssh 收到 `export PATH="/mnt/ssd/.../bin: && ..."`，远端 bash 语法错误。
→ 修法：远端命令整体用**单引号**包裹传 PowerShell（单引号内 `$` 是字面量），命令内部若需单引号再用 `'"'"'` 拼接。与 summary 里"`$HOME` 双引号里被本地展开"是同一坑的第二次踩。
→ 备注：**PowerShell 双引号会本地展开 `$var`，单引号不会**；传 ssh/scp 的远端命令默认单引号包裹。

#99【bash case 匹配】`case "$path" in GPL*)` 对绝对路径永不命中，输入分流静默落空
→ prep_matrix 首版按文件名前缀分流输入（`GPL*` 匹配 GPL 注释、`series_matrix*` 匹配矩阵），但任务引擎传进来的是**绝对路径**（`/mnt/ssd/bio_data/line1_bulk/raw_data/GPL11532-32230.txt`），前缀匹配永远不中，文件没进任何变量，后续 "缺少必需输入" exit 2。
→ 修为模式前后都带 `*`（`*GPL*`、`*series_matrix*.txt.gz`、`*grouping*`），并在代码注释里写明"模式必须前后都带 *：拿到的是绝对路径，前缀匹配永远不中"。
→ 备注：**case 的模式默认锚定字符串开头**，对路径做后缀/包含匹配必须两侧加 `*`。同类风险：任何"按文件名猜内容"的分流，先用真实输入（绝对路径）试一遍再写模式。

#100【数据格式】grouping.txt 数据行第一列是"分组名+长标签"空格拼接、表头行不含 GSM 编号却被外层 grep 收进来，分组核对 fail
→ prep_matrix 与 GEO 元数据派生分组交叉核对，两次踩坑：
  1. 外层用 `grepl("GSM")` 筛数据行，表头行 `GSM 编号` 也含 "GSM" 字样被收进内层，内层 `^GSM[0-9]` 又匹配不上 → 空 → fail。修为外层收紧到 `grepl("GSM[0-9]")`。
  2. `cat -A` 实测数据行结构：第一列是 `皮损组 LS`（分组名与长标签用**空格**拼在同一个 tab 字段里），第二列才是短标签 `L`。原代码取 `fields[2]` 得到 `L`，与 GEO 派生分组 `LS` 冲突。修为 `sub("^.*\\s+", "", trimws(fields[1]))` 取第一列最后一个空格词，并加标签格式断言（`^[A-Z]+$`）。
→ 另修 `readLines(warn=FALSE)`：文件末尾无换行时 incomplete final line 的 warning 会混进 stderr，把 error_log 弄脏。
→ 备注：**下手前先 `cat -A` 看真实字节结构**，别按"应该是 tab 分隔的整齐表"假设；同一行里混用 tab 与空格两种分隔符是常见脏数据形态，解析要按字段逐个 `trimws` + 正则取，不按下标猜。

#101【链路中断】Termux 主进程被 MIUI 杀掉，任务执行中途 ssh exit 255，该次任务无台账无产物、静默消失

#102【浏览器自动化】chrome-devtools MCP 的 fill 工具对 React 受控 `<textarea>` 不生效：DOM 值没进 React state，提交时拿到空 inputs
→ 界面验收 prep_matrix 时，用 fill 工具写两个多行输入框，工具报成功，但提交后脚本报 `缺少必需输入：series_matrix 与 GPL 注释都必须提供（当前 sm='' gpl=''）`。`evaluate_script` 回读 textarea DOM 值为空串。同一次操作里单行 `<input>`（步骤名）却成功了。
→ 根因：fill 工具直接赋 `element.value` 后派发的事件过不了 React 的值追踪器（React 18 受控组件比对 last value，直接赋值被判定"无变化"，onChange 不触发，state 不更新）。textarea 与 input 走的填充路径还有差异。
→ 修法（无需改项目代码，是验收手法问题）：`evaluate_script` 里取 `HTMLTextAreaElement.prototype.value` 的**原生 setter**，`setter.call(el, text)` 后 `dispatchEvent(new Event('input', {bubbles:true}))`，这是 React 受控组件的标准兼容写法，一次成功，随后提交 exit 0 全链路通。
→ 备注：**自动化工具"报成功"不等于状态真的进了应用**，提交结果与回读 DOM 要互相印证。以后界面验收填多行受控组件，直接用原生 setter 路线，不跟 fill 工具纠缠。
→ **复发记录**：2026-10-13 S4 步骤 1 ingest_spatial 界面验收再踩一次（会话未先搜本台账）：fill 填 inputs/outputs 两个 textarea 后提交，脚本报"缺少必需输入"exit 2，台账 397dff91 failed；服务器台账 io_files.input 为空数组实锤 state 没拿到值。原生 setter + input 事件重填 + fetch 拦截器验证提交体后 55s 跑通（台账 8a28a18e）。**教训升级：界面验收动手前先搜本台账相关编号**。

#103【数据形态】line2 GSE254707 盘点三连坑：CRLF 行尾让 awk 报"全非零"假象；GEO RAW.tar 外层不压；soft 元数据与沉积文件计数口径不同
→ S3 数据盘点连续三个"数据在骗人"：
  1. 单细胞计数文件是 **CRLF 行尾**。awk 里 `$2 > 0` 对带 `\r` 的值触发**字符串比较**：`"0\r" > 0` 为 TRUE，于是 33218 个基因"全非零"，与 `head` 看到的前 20 行全是 0 直接矛盾。修法：`cat -A` 看行尾（`^M$`），统计改走 Python `int(line.split("\t")[1])`（tolerant `\r`）。
  2. `GSE254707_RAW.tar` **外层是纯 tar 不压**（GEO RAW.tar 一贯如此），`tar -tzf` 报 `gzip: stdin: not in gzip format` 且列表示为空；内层 `GSM*_*.txt.gz` 才是 gzip。修为 `tar -tf` / `tar -xOf ... | zcat`。
  3. soft 的 `ncount rna`/`nfeature rna` **剔除 ERCC spike-in**，`percent.ercc` = ERCC/(总量含 ERCC)；与 deposited 计数文件有 ≤0.24% 的再定量残差（782/4988 细胞三项精确一致，其余小幅偏差，对不上任何 `__` 汇总行）。修法：ingest_counts 对账用 1% 容差 + ERCC 剔除口径，精确匹配率单独报告，不静默吞差异。
→ 另记数据定性结论（防后续会话重新踩）：GSE254707 = Smart-seq2 孔板单细胞（每 GSM = 一细胞，4988 个），**不是 10x 目录**；区域码 PP=皮损(LS)/PN=非皮损(NLS)/H=健康(HC)；文件尾 5 行 `__no_feature/__ambiguous/__too_low_aQual/__not_aligned/__alignment_not_unique` 是 featureCounts 汇总行，必须排除出矩阵。
→ 备注：**awk 的数值比较遇非数字字符就退化成字符串比较**，`\r` 是隐形触发源；"统计结果与肉眼抽查矛盾"时先查行尾编码，再查比较语义。

#150【并发】Mutex 被强杀的上一实例遗弃后，`WaitOne` 抛异常而不是返回 false，新守护静默退出
-> 现象：`Stop-Process` 杀掉旧守护后，再 `Start-Process` 起新守护，日志一行都不写，

-> 备注：**单实例互斥必须处理遗弃**，否则"改完重启守护"这个动作会静默失败，
   而你以为它在跑。
