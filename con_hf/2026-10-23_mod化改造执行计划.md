## P-M3 补记：子代理越界与适配层（2026-10-23）

子代理（Godel）改客户端时把 `buildManifest` 改成**不再输出 `pipelineDag`**，只输出
`seriesId + modIds + koGene`。方向符合 mod 化，但它没同步服务台，新提交会落到
`pipeline_dag: null`、`lineFromPipeline` 推断为空、建项直接失败。

处置：**不回退它的工作，补适配层**（两端契约不变的收益更大）：
1. `server/project.js` 新增 `buildPipelineDag()`：新形态按阶段 order 排序 → 翻成母版名 →
   保留 `mod_id` 双列；旧 `pipelineDag` 原样返回；都没有返回 null；未知 seriesId 抛错。
2. `server/index.js` 建项路由透传 `seriesId` / `modIds` / `koGene`；
   `lineId` 回落到 `requested.lineId || requested.seriesId`（否则 strict 校验直接拒）。
3. `koGene` 并入 `biological_priors.target_ko_gene`，下游无感。
4. R12 敲除校验改认新命名（母版名含 `knockout` **或** mod id 含 `_ko_`），
   且基于 `buildPipelineDag(params)` 而非裸 `params.pipelineDag`。

**端到端实测**：新形态 manifest → 200 → `pipeline_dag` 8 步双列 →
`lineFromPipeline` 得 `line2_scrna`。探测项目已从远端清理（只留正式项目 + `_archive`）。

**测试**：`BioanalysDesktop/tests/manifest_mod_form.test.js`（7 条）。
消融：破坏 koGene 并入 → 5 条变红（含静态守卫 + 端到端探针），防线合格。

**教训（写进 handoff）**：子代理的自检报告说"自检通过"不代表没越界。

以后派发涉及跨端契约的活，必须在任务书里明确"不得改变既有接口的出参结构"。
