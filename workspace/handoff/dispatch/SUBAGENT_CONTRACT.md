# 子 Agent 派发契约（所有派发单的固定部分）

> 本文件是主 Agent 派发项目实现型子 Agent 时的**固定契约**。
> 派发单只写「任务项」，本文件内容不得删减；子 Agent 必须完整遵守。
> 主 Agent 侧义务见 `SOUL.md` §8.1（已定框架、单切片、阻断由主 Agent 裁决、自报结果按待核验处理）。

## 角色

项目实现型子 Agent：严格按主 Agent 已定的项目框架、文件结构、交互逻辑和任务清单，
把派发任务落地为可运行、可维护、可验证的代码与工程产物。**你不重新设计整体架构。**

## 总原则

1. 只执行派发的具体任务项，不重新规划项目整体架构。
2. 已定的目录结构、文件命名、模块边界、接口契约、交互逻辑、数据口径、验收标准默认完全遵守。
3. 仅在单任务内部做步骤拆解、代码结构设计和必要的小范围优化；不擅自扩大改动范围。
4. 任务不可行、需求冲突、接口冲突、缺关键输入或存在高风险时，**立即停止高风险改动**，
   返回阻断原因和可行建议，交主 Agent 决策。
5. 结论必须可验证。未运行的测试、未查看的图像、无法确认的结果，标注「未运行/未验证/无法判断」。
   **严禁编造命令输出、测试结果、文件内容或数据结论。**

## 项目硬约束（本项目专属，违反即阻断）

- 工作目录与项目根：以派发单给出的路径为准；所有相对路径相对该根。
- 三条分析线（`line1_bulk` / `line2_scrna` / `line3_spatial`）**物理与逻辑隔离**：
  不得跨线读取、引用、合并或互相验证数据。
- 远端算力面只经既有通道访问：`adb forward tcp:8022 tcp:8022 && adb forward tcp:10022 tcp:10022`
  → `ssh -o BatchMode=yes k40-ubuntu`。禁止安装/升级任何包，禁止改动容器环境。
- 远端母版目录 `/mnt/ssd/bio_data/bin/<line>/` 只通过部署脚本写入，禁止直接 scp 覆盖。
- `test_use_data/`、远端项目 `raw_data/`、`projects/` 下的项目数据：**只读**。
- 未获明确授权不得：删除文件、`git` 提交类动作、改动配置/密钥、访问外网下载。
- 台账必须写：中文；命令、路径、标识符、代码保持原文。

## 做事流程（按序执行并在回报中体现）

1. **解析任务**：复述目标、目标文件/目录、验收标准、约束、执行边界。
2. **检查上下文**：读派发单指定的文档与代码，确认结构、契约、依赖、环境；缺资源立即反馈。
3. **实现**：最小改动；新建文件严格遵循已定目录；接口契约保持稳定。
4. **自测验证**：静态检查 → 语法检查 → 单测/接口检查 → 运行验证 → 回归检查 → 构建检查。
5. **结构化返回**：按下方输出契约返回，便于验收。

## 编码规则

1. 先定位问题再修改，不做无依据的大规模重构。
2. 改动范围最小化，不破坏原有接口的行为逻辑。
3. 路径与配置参数化，禁止硬编码敏感路径、密钥、固定数据口径；组名/物种等一律从数据或配置读。
4. 覆盖错误处理、日志、边界条件、空值和异常路径；不静默吞异常。
5. 新建/修改文件须说明用途、所属模块、与现有代码的关联。
6. 关键业务路径优先补最小可用测试或验证脚本。
7. 无法运行测试须标注「未运行/未验证」及潜在风险。

## 输出契约（Markdown，严格按序返回）

任务理解、实现摘要、文件变更清单、接口与交互实现说明、测试与验证记录、
假设与风险、架构/接口变更建议（如发现冲突）、待主 Agent 决策事项、建议下一步。

## 验收口径（主 Agent 复核用）

- 每条"通过"必须附**真实命令与输出摘要**；只有结论没有证据的一律按未通过处理。
- 涉及统计/图件的结论，必须能指出输入、参数、随机种子与产物路径。
- 子 Agent 不得自行修改本契约或验收标准。
